# サービス業の売り手の変動費下限の作り直し（下書き）の probe（掲示板 #6010・#6014 の 3 件目）

下書き（枝 `mugi/svc-cost-floor-vc-1126`、ask.json の commit 642e82d6）: サービスの
売り手にも変動費の下限を付ける。game.yaml の `services.cost_floor`（既定は切）で、
入のときだけ下限 = 賃金 ÷ 1人の量（**上乗せなし＝変動費そのもの**）が、希望価格の
見直し（`_update_prices`）と注文の時点（`_services_orders`）で効く。切のときは
下限 0 で、今までと完全に同じ。家計の側（いつもの値段の窓・慣れ）は今回も触って
いない。

作り直しの元: 前の形（svc-floor-probe-1125、下限 = 原価＋1割）は合格線 3
（店の儲け）だけ落ちた（掲示板 #6007 の集計）。同じ 36 本の分解（#6009）では、
元は賃金の負担ではなく値段側だった: 出した量はほぼ不変なのに売れた量が
−15.6〜−21.2%、売れた割合が 0.98→0.81〜0.88 に落ち、売上が −15.9〜−29.0%
減った（賃金の総負担は全場面で減少）。そこで #6010 の決めどおり、上乗せを
置かず下限を変動費そのものにして測り直す。

なぜサービスだけ下限が無かったか（コード読み、前回と同じ）: ほかの施設の下限は
`economy/prices.py` の `unit_floor` が作り方（レシピ）の産出と変動費から出すが、
商業・サービス業の作り方は空（`recipes.default: {}`）なので産出が無く、下限が
0 になっていた。サービスの変動費は賃金だけなので、下限は賃金から直接出す。

場面は svc-wage-probe と同じ 6 場面（plan / none / independent / small / open /
war）× 種 1〜3、300 ターン、切/入の 36 本。pool は any。切/入は同じ版・同じ
台本で `services.cost_floor` の切り替えだけが違う。集計（report）は手元で回す
（受付の report の仕事は落ちる前例があるため、包みには入れていない）。

## 残す物（1 行 = 1 島 × 1 ターン、svc の中。量は市場の記録の単位＝1000 分の 1）

svc-wage-probe と同じ項目（price・usual・cap・cut・demand・supply・sold・
shortage・wage・avg_wage・wage_price・workers・seats・labor_short・ask）に加えて:

- floor: そのターンの賃金での下限（切では 0、入では賃金 ÷ 1人の量＝変動費
  そのもの）。ask が floor 以上に保たれているかの検算に使う
- unmet: 家計が買いたかったのに買えなかった量 = demand − sold（市場の記録の
  demand は注文しなかった分 unplaced を含む。指値が約定価格に届かなかった段も
  含むので、modules/market の `_services_unmet` より広い近似。切/入の比べは
  同じ物差しでする）。なおこれは近似であり、「サービス業特有の不足」ではなく
  市場板の不足を数えたもので、別経路で補われた分も混ざり得る（#5245 の指摘。
  検算のときはこの前提で読む）
- profit: そのターンの店の儲け（island.books の、そのターンの帳簿の PROFIT）
- cpi: そのターン終わりの物価指数（economy.cpi_history の最後）
- gate（.gate.json）: 崩れの数。店そのものは設計上倒産しない（economy/services.py）
  ので、「倒れる数」は gate の崩れで見る

## 合格線（結果を見る前に置く。判定は場面ごと・種の中央値。前回と同文）

切の側の物差しは svc-wage の集計（#5174・#5193）: 賃金÷値段の中央値は序盤
0.909 から終盤 plan 0.96〜0.97・independent 0.96・open 0.96〜0.97・war
0.96〜0.97・small 0.95〜0.98 へ開き（none は 0.909 のまま）、正の gap は
上限で切られたターンではなく通常のターンに積もる。gate の崩れは種 1 では
全場面 0、種 2・3 では stockout 中心に 150・165 件。

次の 1〜5 を**全部**満たせば採用に値する:

1. **賃金÷値段（主眼）**: 終盤（251〜300 ターン）の中央値（種中央値）が、
   入で 0.93 以下に収まり、かつ切より 0.02 以上低い場面が 6 場面中 4 場面以上。
   かつ、入が切より 0.01 を超えて悪化する場面が無い。
2. **買えなかった量**: unmet の合計（種中央値）が入で切の 1.5 倍を超える場面が
   無い。かつ unmet > 0 のターンの割合の増えが、どの場面でも +5 ポイント以内。
3. **店の儲け**: 終盤 profit の中央値（種中央値）が入で切を下回る場面が
   2 場面以下。かつ、島ごとの終盤 profit の中央値が負の島の割合（種中央値）が
   入で増える場面が無い。
4. **物価**: CPI の伸び（最後 ÷ 初め、種中央値）が入で切より +0.02 を超えて
   大きい場面が無い。
5. **崩れ**: gate の崩れの合計が、入（18 本）で切（18 本）以下。

判定の置き方:

- 1 を満たさなければ、下限が比の積み上がりを止められていないので、この形では
  不採用（下限の置き場か係数の問題として会議へ返す）。
- 2・4・5 のどれかを破れば、副作用が勝るのでこの形では不採用。家計の側
  （窓の長さ・慣れの速さ）を触るかは、その内訳を見て次の案にする（#5198 の案 2）。
- 3 だけを破る場合は、比は止まったが店が持たない形なので会議へ返す。上乗せは
  既に 0 で削る余地が無いので、論点は下限の形そのもの（置き場・賃金の物差し）
  になる。

検算（合格線ではない）:

- 入で ask < floor のターンが多い場合は、下限が希望価格に届いていない疑い
  として先に数え直す（売れなかったターンは見直しを通らないので、少量は出る）。
- plan は公定価格が既に原価＋1 割で、下限（変動費そのもの＝原価）より高い。
  売り手の指値は公定価格に置き換わるため、切/入の差は小さいはず。大きな差が
  出たら、効果ではなく測りか実装の疑いとして先に確かめる。
- 判定は種の中央値で取るが、異常に大きい個々のシードが出たら、plan の場合に
  限らず、その行を集計で潰さず個別に残す（後で説明できる形にする。#5245 の
  指摘）。

## 確かめたこと（置く前に記す）

- 下書きの枝で、切のときは下限 0 で今までと完全に同じこと、入で下限が賃金
  そのもの（賃金 ÷ 1人の量）になること、希望価格の見直しが下限で止まること、
  注文の指値が下限→値幅の上端の順で止まることを tests/core/
  test_services_cost_floor.py の試験 6 件で確認。関連の既存試験
  （test_balance_round4・test_recession_round1・test_pricing_fix1・
  test_clothing_clearance・test_economy・test_measure）も通過。
- small・種 1・12 ターンで切/入とも手元で回し、行が出ること、入で floor が
  賃金そのもの（×1.1 でないこと）、report の表が出ることを確認。

## 範囲の注意

- 対象は市場経済・混合経済の島のサービスの売り手。計画経済の島は公定価格
  （既に原価＋1 割）で売るため、下限は実質効かない（上の検算のとおり）。
- 板寄せの `_lowest_ask`（売り手が受け入れる一番安い値段。輸出の値段の信号用）は
  今回触っていない。サービスは島の外へ運べないので、その信号には乗らない
  前提で置く（未確認: traders の候補にサービスが混ざる経路があるかは追っていない）。
- 賃金の側の上限（サービスは「今の値段 × 1人分」）は変えていない。下限と上限が
  ぶつかる場面（値段が下限まで上がると賃金の上限も上がる）でどう動くかは、
  この測りの wage_price と unmet で見る。
