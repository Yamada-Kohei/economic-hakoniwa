# H-7: 500 ターンの写しから続けても同じになるか（台帳 C3、掲示板 #5365 の C）

速くする束（W-236）の残り H-7。「同じ場面・同じ種の 1200 ターンを、
500 ターンの写しから続けても、最初から回したのと同じになるか」の確かめ。
H-3 の土台（測りを途中の写しから続ける設計）は main 入り済み
（#436・#452・#459）。この包みは、その写しが本当に進行を変えないかを
1200 ターンで見る。

## 構成

- 版: main の 0728d118（配置時に ask.json の commit へ固定）
- 場面 1 つ（open）× 種 1 つ（1）、1200 ターン、2 本 + report
  - full: 最初から 1200 ターン
  - resume: 500 ターンで写しを取り、作り直してから残り 700 ターン
- 回す機械は ESPRIMO か HAL（#5365・台帳 C3 の指定）。提出は
  claude-hakoniwa-2。

## 写しの取り方

本番のバックアップと同じ道を使う: `hakoniwa_core.state.serialize` の
`world_to_dict` で dict にし、JSON を往復させて（バックアップは DB の
JSON に残る形）`world_from_dict` で作り直す。server/turns の
`_make_backup` / `load_backup` と同じ組。

写しに入らない物（serialize の `_TRANSIENT`）: 島の stats・scratch・
journal・trades・markets・books。これらは毎ターン作り直される前提で、
それでも最終ターンが一致するかを見るのがこの測りの眼目。

あわせて、resume の実行では写しを取るターンで、往復の直前と直後に
`hakoniwa_core.simulate.world_digest`（写しに入る欄の指紋）を取る。
指紋が割れたら実行はその場で止まる（本実行なら 500 ターン目で効く
ので、1200 ターンまで回してから気づく形にならない）。指紋は写しに
入る欄だけの物なので、`_TRANSIENT` の欠落（trades 等）は原理的に
映らない — 逆に、割れたら serialize 側の状態の欠落と切り分けられる。
指紋は resume の出力 JSON に `snapshot_digest_before` /
`snapshot_digest_after` として残り、report も判定に含める。

## 合格の線（事前に固定）

1200 ターン目の国ごとの主な数 4 つが、full と resume で全部の国とも
一致すること:

- GDP（島の統計の `gdp`）
- 人口（`population`）
- 国庫（`treasury`）
- 失業率（`unemployment`）

比べ方はそのままの値の一致（丸め・近さの許容なし）。report は島ごと・
数ごとの表と、合格/不合格の判定を出す。不一致の島・数があれば、
そこが「写しで落ちている状態」の入口になる。

前提としてもう 1 つ: resume の写しのターンで、往復前後の指紋
（`world_digest`）が一致すること。割れたら実行自体が止まるので、
その resume の本は数えない。

## 読み方

- 合格なら: 測りを途中の写しから続ける使い方（H-3 の狙い）は、
  少なくともこの場面・種では進行を変えない。
- 不合格なら: ずれた数と島を見る。GDP だけのずれは統計の作り直しの
  問題、人口・国庫までずれれば状態そのものが写しで落ちている。
  どの状態が落ちたかの切り分けは、次の調べの仕事（この包みの範囲外）。
- 指紋が合うのに最終数が割れたら復元直後のターンの命令（trades 欠落）を疑う。

## 煙確認（配置時にまず回す短い確認）

small・種 1・12 ターン（写しは 5 ターン目）で full / resume / report を
回し、(1) 写しの往復で落ちないこと、(2) report が表と判定を出すこと、
(3) 判定が合格になること、(4) 写しのターン（5 ターン目）で往復前後の
指紋が一致すること（resume の出力 JSON の `snapshot_digest_before` /
`snapshot_digest_after` で確認できる）を見る。本実行（1200 ターン）は
受付の配備の現行方針に従い、この包みでは回さない。
