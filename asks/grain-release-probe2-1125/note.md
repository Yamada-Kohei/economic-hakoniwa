# 国の倉庫の穀物の先行放出（下書き第 2 版）の probe（掲示板 #5091 の決定・#5093 の計画）

下書き第 2 版（枝 mugi/food-reserve-price-lead-v2、ask.json の commit）: 発火の判定は
第 1 版と同じ（直近の約定値が、直近 window ターンの値段の移動中央値の multiple 倍以上、
または rise_turns ターン前から rise 以上上がった、のどちらか）だが、出す量が全量でなく
小出しになり、倉庫に下限が付く。game.yaml の food_reserve.price_lead（既定は切）。

第 1 版（全量放出）は会議で不採用になった（#5090 の集計・#5091 の決定）: 先行放出は
発火したが、飢えターンは減らず、値段の最大はむしろ上がり、倉庫が先に細った。
「全量を一度に出す」形が、後半の跳ね止めの分まで先に使ってしまうと読まれた。

## 第 2 版の量と下限（根拠）

- 足りる分: 前のターンの市場の記録の買えなかった量（demand − volume）が値段を
  押し上げている不足分。記録の demand は今の値段での買いたい量なので、基準の
  値段で買えた量に直すため price/base を掛けて割り増す（同じ予算で買える量は
  値段に反比例する）。見積もりであり、値段は 1 ターンに市場の値幅（market.band
  = 0.10）までしか動かないので、1 回で基準まで戻すのではなく、線が続く間は
  毎ターン小出しにして近づける形。市場の記録（island.markets）はターンの初めに
  消えるため、市場の段の終わり（_record）が、入のときだけ買えなかった量を
  economy.ext（reserve.LAST_UNMET）に残し、次のターンの判定が読む。
- 割合上限: 上の見積もりと同時に、1 ターンに倉庫の量の max_fraction（0.25）まで
  （#5095: 上限と下限は同時に効かせる。中央値に戻す分だけでは、薄い相場で
  全量に張り付くため）。
- 倉庫下限: 住民の食べる量の floor_turns（1）ターン分は先行放出では残す
  （下限 = 目安 × floor_turns / turns。目安は turns=2 ターン分）。飢えの線の
  放出は今までどおり全量で、下限も使う（この切り分けは試験で固定した）。

場面は quick と同じ 6 場面（plan / none / independent / small / open / war）×
種 1〜3、300 ターン、切/入の 36 本。pool は any。

## 残す物（1 行 = 1 島 × 1 ターン、grn の中。量は市場の記録の単位＝1000 分の 1）

第 1 版の項目に加えて:

- ratio / rise3: ターン開始時点の last/base と、rise_turns ターン前からの変化率。
  発火しなかったターンでも残す（後の線引き調整用。#5075）。report で非発火
  ターンの最小・最大を出す
- floor: 第 2 版の下限の量（ターン開始時点）。warehouse_start: ターン開始時点の
  倉庫の量
- release_need / release_floor / release_cap / release_stock: 先行放出のときだけ。
  量の見積もり・下限の量・どの上限で量が決まったか（need / fraction / floor）・
  放出を決めた時点の倉庫の量（#5095 のログ項目: 発火種・放出量・前後価格・
  残量・下限到達。放出後の価格は次のターンの行の price と release_ask の
  比べで report が分類する）

## 集計（report）と合格線

場面 × 種ごとに切/入を並べる表（第 1 版と同じ物差し）に加えて:

- 合格線での判定（#5091）: 「飢えターンと値段の最大が、切より大きくならず、
  少なくとも半分の場面で小さくなる」。判定は場面ごと・種の中央値で行い、
  値段の最大の最悪種は参考として併記するだけ（判定には使わない。#5097）
- 下限の効き方と発火の分類（種の合計）: 量が決まった上限の内訳（need /
  fraction / floor）、倉庫が下限以下で終わったターン数（下限に張り付いた
  ターン数。#5097）と到達の有無、発火後に次のターンの値段が放出の指値より
  さらに上がった回数（スパイクの続き）、下限まで出して終わった発火の回数、
  放出割合（量 ÷ 放出前の倉庫）の中央値。下限の線は切の側にも同じ式で
  引いて比べる（切では下限の仕組み自体はないので、参考の線）
- 非発火ターンの線までの距離（入）: ratio と rise3 の最小・最大

## 確かめたこと

- 下書きの枝で、切のときは今までと完全に同じ（price_lead が None を返し、
  判定に触れず、ext にも残さない）こと、入で倍率の線・上がりの線・中央値の
  跳ね耐性が効くこと、第 2 版の量が見積もり・割合上限・下限で決まること、
  下限が飢えの線を止めないことを tests/core/test_recession_round1.py の
  試験で確認（置く前に記す）
- small・種 1・12 ターンで切/入とも回し、行が出ること、入で先行放出が
  見積もりの量（cap = need）で発火すること、report の判定・分類・距離の
  表が出ることを手元で確認（置く前に記す）

## 範囲の注意

- 対象は既定の備蓄（_reserve_orders）。決まった注文（standing）の reserve 型の
  島の放出（standing.release）はこの下書きでは触っていない
- 計画経済の島は公定価格＝いつもの値段なので、値段の上がりの線は基本的に
  発火しない（飢えの線は今までどおり）
- 判定に使う値段は注文を出す時点で決まっている直近の約定値（前のターンの
  値段）で、1 ターン遅れは第 2 版でも残る（#5010・#5013 の読みのとおり）
