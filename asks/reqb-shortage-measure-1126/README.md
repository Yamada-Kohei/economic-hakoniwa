家計が品切れで代わりを買ったとき、本来ほしかった量を値段と作る量に伝える仕組み
（倭国さんの要望 B）。実装は PR #527 で main にマージ済み（切り替え
`market.shortage_response`、既定は切）。この包みは、その測りを行うための物。

- 版: main `7c948cb5eb23a26287a50a7397eab259a6fa23de`（PR #527 = 3730545d を
  含むことを祖先確認済み。ask.json の commit）
- 場面: none を除く 5 場面（plan / independent / small / open / war）× 種 1〜3、
  300 ターン、切/入の 30 本。pool は any
- none を外す理由: #5417 で場面の作りどおりと確かめられたため、主の比べから
  外すことが最終形（#5427）で決まっている
- 切/入は同じ版・同じ台本で、`market.shortage_response` の切り替えだけが違う
  （台本の --off/--on で config をその場で切り替える。game.yaml は書き換えない）
- 集計（report）は手元で回す（受付の report の仕事は落ちる前例があるため、
  包みには入れていない）

## 仕組みのあらまし（PR #527 の実装）

- 買い手: 入のとき、前ターンに supply（量の不足）で買えなかった原料も、
  price のときと同じく買い上がりの対象にし、指値を 1 ターンに値幅ずつ上げる
  （上限は従来どおり input_limit = 変動費の利益が 0 になる値段）。切では従来
  どおり price だけ
- 売り手: 島の買えなかった量（需要 − 約定）を、独立採算で値段が変動費の下限の
  1.2 倍超（expand_margin）かつ増やせる施設だけに、「増やせる余地 = 全力の
  産出量 − 見直す前の操業目標に当たる産出量」の割合で配る。加算の島合計は
  買えなかった量を超えない。1 ターンの変化上限 0.2 はそのまま
- 計画経済の国営施設は planning.target 側のままで、配分からも除外（別ラベル。
  行に regime を残してあるので、集計で体制別に分けて読むこともできる）

## 残す物（1 行 = 1 島 × 1 ターン。量は市場の記録の単位 = 1000 分の 1）

- markets: 全財の市場の記録（price / demand / supply / sold / shortage）
- cpi: そのターン終わりの物価指数
- cotton_prod: そのターンの綿の産出量（stats の production.cotton）
- mill_rate: 衣料を作る施設の稼働率の平均（#5412 の見る物「衣料工場の稼働率」）
- cotton_orders: 綿の板寄せの注文単位の写し（#5404 の ①〜④ と #5397）。
  台本が市場の段の関数の戻りと板寄せの結果を読むだけで、ゲームの挙動は
  変えない（確かめたこと参照）
  - buys: 注文ごとに {fid, kind, qty（注文量 = ② の注文量）, bid（実際の指値
    = ① の実際の指値）, pri, filled（約定量 = ② の約定量）,
    plost（③ 優先度落ち: 自分より高い指値か、同じ指値で高い優先順位の買いが
    約定した量）, need（④ の元: 資金で削る前の要る量）,
    ilimit（① の input_limit）, fcut（④: need − qty = 資金で削られた量）}
  - sells: 施設ごとに {fid, stock（出した時点の綿の在庫）, offered（出した量）,
    sold（売れた量）, pout（priced_out: 売り指値が約定価格より高くて約定の
    対象にならなかった量）}（#5397 の畑の産出物の在庫と offered・sold・
    priced_out）
  - need / ilimit が付くのは、施設の原料注文の通常の道（_facility_orders）で
    作られた注文だけ。それ以外の道で作られた買い注文は need / ilimit が
    null で、fcut も null（資金削りの合計には数えない）

## 合格線（結果を見る前に置く。#5406・#5412・#5425・#5427 のまま）

主の比べは 5 場面 × 種 1〜3、切と入。判定は場面ごと・種の中央値。

1. **衣料の長い品切れ**: 3 ターン以上続く品切れの件数と量が、切より減る
2. **綿の品切れの割合**: 綿の市場の品切れの島ターンの割合が減る。ただし合格は、
   綿の産出量が増えていて、かつ資金で削られた量が増えていないときだけ
   （#5412・#5425 で固定）。あわせて見る物: 資金で削る前の要る量と約定量の差、
   綿の産出量、衣料工場の稼働率を、同じ場面・同じ種の切/入で並べる
3. **値段の許容幅**: 300 ターン目の CPI は、入/切の比が 1.10 以下か、切の
   種 1〜3 のばらつき（最大と最小の比）の内、どちらか広い方まで。綿の約定価格の
   300 ターンの中央値は、入/切の比が 1.5 以下。どちらかを超えたら不合格で、
   上限の当たり方を読み直す。その切り分け用に、input_limit の値・実際の指値・
   limit に届いた注文の割合を切/入で並べる（report の「limit の切り分け」）
4. **崩れ**: quick の崩れが種のゆらぎの内
5. **ほかの原料**: 衣料以外の原料（鉄鉱石・原油など同じ道を通る物）で
   品切れが増えない

## 確かめたこと（置く前に記す）

- small・種 1・100 ターンで切/入とも手元で回し、行が出ること、綿の注文の
  写し（need・ilimit・fcut・plost、畑の stock・offered・sold）が取れること、
  report の表が出ることを確認
- 包むだけの写し取りが挙動を変えないこと: 同じ small・種 1・100 ターンを
  包まない素の実行と比べ、全 400 島ターン・全財の市場の記録（値段・需要・
  供給・約定量）の差が 0 であることを確認
- 実装の試験は PR #527 の CI で通過済み（tests/core/test_shortage_response.py）

## 範囲の注意

- 資金で削られた量（fcut）は「要る量 − 注文量」で数える。量を変えるのは
  資金の段（_afford）だけで、指値の買い上がり（_raise_bids）は量を減らさない
  作りであることをコードで確認済み。注文自体が出なかった分（指値 0 で
  price として記録される分）は fcut に入らない
- priced_out は「売り指値 > 約定価格で、約定の対象にならなかった量」の定義で
  数える。指値なしの売り（腐る物など）は対象外
- 台帳の 1 行（#5418、民営の組の参入が none で一度も発火しない件）は、
  #5562 の段取りどおり包みの後でよいとされているので、この包みには含めない
- plan/inbox.md はリポジトリ内に無く（共有フォルダ側）、この VM からは
  読めなかった。14-plan・台帳とは突き合わせ済みで、矛盾なし（台帳 C1 の
  「倭国さん要望 B は切り替えは切のまま、次は綿の作る量の決め方」と同じ
  位置づけで、測りがその次の一手）
