# 家計の電気 LB-47（power.household_curve）の測り直しの包み（掲示板 #5249・#5250・#5260・#5356、引き継ぎ第 2 弾の件 21 = #6302）

家計は電気を買える分だけ買う仕組み（LB-47、2026-11-12 に実装、切り替え
`power.household_curve`、既定は切）。本人の答え（#5249）で「測り直してから
決める」となり、今の main で切と入を比べ、11-13 の悪化（取引の止まり約 2 倍・
貿易の途絶え・失業 +13%）が今も出るかを見る。悪くなければ既定を入にする。
この包みは、その測りを行うための物。

- 版: main `6f4c4ba8d284fc85e3a5621cc0871e3337fad17e`（ask.json の commit。
  game.yaml の `power.household_curve` は false = 切であることをこの版で確認済み）
- 場面: quick と同じ 6 場面（plan / none / independent / small / open / war）
  × 種 1〜3、300 ターン、切/入の 36 本。pool は any
- 切/入は同じ版・同じ台本で、`power.household_curve` の切り替えだけが違う
  （台本の --off/--on で config をその場で切り替える。game.yaml は書き換えない）
- 集計（report）は手元で回す（受付の report の仕事は落ちる前例があるため、
  包みには入れていない）

## 仕組みのあらまし（LB-47）

- 切（前の形）: 家計の層ごとに 1 本の注文。指値は使う額の `power.household_share`
  ÷ 要る量で、電気料金がこれを超えると層の全員が買わない（全部か 0 かの崖）。
- 入: 家計の層は、いつもの電気料金を真ん中に、高い段ほど少なく買う段の注文
  （`household.price_curve` の倍率と `power.household_band_steps` の段）を出し、
  払う額は使う額の `power.household_share`（と、使う額から食べ物の見込みを
  除いた残り）まで。計画経済の公定価格の島はどちらの形でも今のまま（公定価格で
  要る量を注文し、配給で分ける）。

## 残す物（1 行 = 1 島 × 1 ターン）

- unemployment: そのターンの失業率（記録の段と同じ式の stats）
- trade: 輸出＋輸入（貿易の途絶えの材料）
- power_shortage: 電気の不足率（1 − 使えた量 ÷ 要る量）
- power_demand / power_used: 電気の要る量と使えた量
- power_short_supply: 要る量のうち、発電が全部売れて届かなかった割合（本当の
  電力不足）
- power_unaffordable: 家計の要る量のうち、発電が売れ残っているのに電気料金を
  払えずに使えなかった割合（家計の電気の買えなかった量の主の物差し）
- home: 家計の層ごとに届いた割合
- gate（.gate.json）: 崩れの数と明細（取引の止まり = 崩れの no_trade）、
  目安外れの種類ごとの数と貿易の途絶え（trade_stopped）の明細。目安外れは
  1 ターン目から数える（崩れと同じ窓）

## 合格線（結果を見る前に置く。#5250・#5260 のまま）

主の比べは 6 場面 × 種 1〜3、切と入。入が次の 3 つを全部満たせば既定入に
進める。1 つでも外れたら、既定入は勧めず、結果と読みを会議に置く。判定は会議。

1. **取引の止まり**: 入が切に比べて、止まり（gate の no_trade）の増えが種の
   ゆらぎの内。report では、全体の合計（入/切）と、場面ごとに切の種の幅
   （最小〜最大）と入の種の値を並べて読む
2. **貿易の途絶え**: 入で途絶え（輸出＋輸入が 1 年続けて 0。gate の
   trade_stopped）が出ない
3. **失業率**: 入と切の差が種のゆらぎの内。report では場面ごと・種の中央値で、
   全ターンの平均と終盤（251〜300）の平均の両方を並べ、差と切の種の幅の
   広さを比べる

あわせて並べる物: 電気の不足率、家計の電気の買えなかった割合、本当の
電力不足の割合（場面ごと・種の中央値、切→入）。

基準点: 11-13 の悪化は「取引の止まり約 2 倍・貿易の途絶え・失業 +13%」
（当時は船が寿命で減って戻らない弱さが重なっていた。FX-78〜80 で直し済み）。
今回はその再現の有無を見る。11-13 の記録そのものは X870 の共有フォルダ
（household-power-curve-*-20261112）にあり、今回の比べは今の main の中の
切/入で行う。

## 確かめたこと（置く前に記す）

- 固定した版（main 6f4c4ba8）の手元で、small・種 1・30 ターンを切/入とも
  回し、行（全項目・層ごとの届いた割合）と gate（崩れ・目安外れ・貿易の
  途絶え）が出ること、report の表が出ることを確認
- 台本は市場の関数を包まず、ターンを回した後に統計を読むだけなので、測る
  こと自体は挙動を変えない（gate の Recorder は標準の測りと同じ物）

## 1 回目の投入の失敗と直し（2026-11-27）

- 1 回目の 36 本（受付の仕事 1008〜1043）は、全本が hal で同じ引数エラーに
  より即落ちした（終了コード 2）。エラーの中身:
  `lb47_household_probe.py: error: argument cmd: invalid choice:
  'lb47_household_probe.py' (choose from 'probe', 'report')`
- 原因: ask.json の各 run の `args` の先頭に台本のファイル名
  （`lb47_household_probe.py`）が入っていた。受付は `sys.argv` を
  `[uketsuke-run/<台本名>] + args` の形に組み立てるので、台本名が
  argv[1] にも入り、argparse がそれをサブコマンド（probe/report）と
  誤認した。手元の試走は `python3 lb47_household_probe.py probe ...` の
  形（台本名は argv[0] の 1 つだけ）だったため、この重なりが出なかった。
  通っている包み（deadlock-quick・h7-dict501・grain-rotate 等）は全部
  args の先頭がサブコマンドで、台本名を入れていない
- 直し: ask.json の全 36 本の args から先頭の台本名を取り除いた
  （台本そのもの・合格線・場面・種・ターン数は不変更）。受付と同じ
  組み立て方（manage.py shell + runpy、sys.argv の形も同一）を手元で
  再現し、small・種 1・30 ターン切/入とも通ることを確認してから
  出し直した
