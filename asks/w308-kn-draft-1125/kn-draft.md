# kn の物差しの直しの下書き ― W-308 条件 4 の n の立て方

むぎの下書き。#5074 の決め 3（kn の作り方の粗さは物差しの直しとして台帳に載せ、
次の W 系の測りを決める前に会議にかける）、#5078（HAL の読み）、#5187 の項目 4・
#5191 に沿う。**実装はまだしない**（下書きを会議にかけてから）。
今の物差し（上限 3.0）は #5074 の決め 1 で「替えない」と決まっているので、
この下書きの案はどれも**次の W 系の測り**のための物で、probe12 の結果の合否を
後から動かすためには使わない。

## 0. 前提: kn はどう作られているか（一次情報）

出典は `asks/w308-a-1124/w281_probe12.py`（kn は probe5 で入った。probe13 は
船団 panel 専門で kn を記録せず、probe14 にも kn は無い。kn の記録があるのは
probe12 系だけ）。

- 倍率の段 `GRID`（124 行）:
  `(0.25, 0.5, 0.6, 0.7, 0.8, 0.85, 0.9, 0.95, 1.0, 1.05, 1.1, 1.15, 1.2, 1.3, 1.4, 1.5, 1.75, 2.0, 3.0)`
  の 19 段。
- `kn` の計算 `_k_max`（310〜324 行）: 標準の見積もり運賃 `est`（今の値段の船を
  半分使ったときの運賃 = 運航費 + 資本費 × min(1, 2 × 0.5)、`ships._rate` で計算）
  に対して、運賃を `est × 倍率` に差し替えて見込みを引き直し（`_importable_at`、
  301〜307 行。`ships.freight_rate` を差し替えて `traders.prospects` を読む）、
  **引き合う財が 1 つでもあれば**その倍率は「引き合う」。引き合うかどうかは
  ゲーム側の `importable`（`hakoniwa_core/trade/traders.py`: 輸入の圏が選ばれて
  いて `import_limit > import_price`）。二分探索で引き合う最大の GRID 段を返し、
  GRID の最大 3.0 で引き合えば即 3.0、どの段でも引き合わなければ 0。
- 計算と記録のタイミング: 各ターンの終わりに、商社が動いていて・輸入の見込みが
  なく・自前の船が 0.5 隻未満の島について計算して、前のターンの写し（prev）に
  積む（645 行）。次のターンに条件 4（自前の船 0.5 隻未満かつ `import.freight` が
  0、nt=1）で印が n の島ターンだけ、その値を `kn` に残す（610〜613 行）。つまり
  kn は「前ターンの終わりの状態」で計算された値が、そのターンの印に付く。
- n の数え方（`asks/w308-a-1124/tally/w308_kn_retally.py`、#4847 と同じ）:
  nt=1 かつ印 n で、kn があって `1 <= kn <= 上限`（今は 3.0）の島ターンを n と
  数える。

## 1. 飽和の原因（式と分布から）

kn 再集計（`asks/w308-tally-1125/w308-kn-retally.md`、probe12 の K2・WK、
種 17〜24・plan）の分布: n の全数の中で kn = 3.0 は K2 で 16,383 / 17,348
（94.4%）、WK で 28,174 / 28,648（98.3%）。`1 <= kn <= 2` の中間帯は K2 39 件・
WK 10 件しかなく、しかも全部 901〜1200T にある（151〜900T では上限 2.0・1.5 の
n は 0）。上限を締めると n は K2 16,422 → 39 → 18、WK 28,184 → 10 → 6 と、
減るのではなく消える。

式の側の原因は 3 つ（+ 副次 1 つ）:

1. **any（最大値）の統計量であること**: 判定は「引き合う財が 1 つでもあるか」で、
   kn は島の輸入見込み財のうち最も運賃に強い 1 財の限界倍率。財の数・需要の量は
   式のどこにも入らない。輸入候補の財が多い島ほど、どれか 1 つが 3 倍でも合う
   形になりやすい（読み）。
2. **GRID の右端で打ち切られること**: 3.0 で引き合えば即 3.0 を返すので、
   「3.0 ちょうど」と「3.0 でも足りないくらい強い」が同じ 3.0 に潰れる。
   分布の山は上限の位置にできている。
3. **目盛りの偏り**: 1.0 の前後は 0.05 刻みだが、1.5 の先は 1.75・2.0・3.0 と
   粗くなる。n の本体が張り付く帯域（2.0〜3.0）には目盛りが 1 つもない。
4. （副次）**単調性の仮定**: 二分探索は「引き合うのは倍率の小さい側」という
   前提（docstring 明記）。運賃を変えると圏の選び直しで引き合う財の顔ぶれが
   入れ替わり得るが、kn はその前提で 1 値に潰している。

要するに今の kn は、実質「標準見積もりの 3 倍でも引き合う財が 1 つあるか」の
二値に潰れていて、条件 4 の n はその二値で立っている。これが #5074 の言う
「引き合う財が 1 つあれば上限まで上がる」粗さの中身。

## 2. 直し案の候補

置き場所の前提: どの案も、線（しきい値）は**次の測りの前に会議で固定**する。
測った後に線を動かさない（#5074 の決め 1 と同じ考え）。

### 案 A: kn の素を記録に足す（最小ログ）― HAL #5078 の案

次の probe で、kn と並べて次を残す:

- (a) 標準見積もり（倍率 1.0）で引き合う財の数
- (b) GRID の各段で引き合う財の数（倍率 → 財の数の列）
- (c) 倉庫の薄さの材料: その島ターンの倉庫（島の状態の `warehouse`）の在庫。
  どの財・どの単位で残すかは決めが要る（候補: 輸入見込み財の在庫の合計、
  または倉庫全体の量）

続いたターン数は marks・nt・kn の並びから集計側で数えられるので、記録の追加は
要らない。

- 利点: 測り直しなしに案 B〜D の線引きを記録だけで試せる（kn 再集計が記録
  だけでできたのと同じ強み）。probe 側の変更は `_importable_at` の any を
  「数える」形にするのが中心で小さい。
- 欠点: n の立て方そのものは次の会議まで今のまま。記録は kn より大きくなる
  （島ターン × 段の財数）。

### 案 B: n を「引き合う財の数」で立てる（広がり）― #5187 の形の軸

- 定義案: 条件 4 の島ターンのうち、標準見積もり（倍率 1.0）で引き合う財が
  K 個以上ある物を n とする（K は会議で固定。kn >= 1 の代わりに使うか、
  kn と併用するかも会議で）。
- 利点: 「1 財だけ例外的に合う」島ターンを落とせる。今の n の本体が 1 財で
  立っているのか複数財なのかが、初めて判定に入る。
- 欠点: 財の数の分布は今の記録に無いので、probe12 の過去分には適用できない
  （kn しか残っていない）。K をいくつに置くと n がどう動くかは、案 A の記録が
  揃うまで読めない。

### 案 C: n を「続いたターン数」で立てる（継続性）

- 定義案: 印 n かつ kn >= 1 の島ターンが、同じ島で L ターン以上連続した区間に
  属する物だけを n とする（L は会議で固定）。
- 利点: **今の probe12 の記録だけでも数え直しができる**（marks・nt・kn は
  島ごとにターン順に残っている）。下の参考数がそれ。
- 欠点（参考数が示すこと）: 効きが弱い。n の大半は長い区間に属していて、
  孤立した 1 ターンは少数。継続性だけでは物差しの粗さは直らない。
  K2→WK の開きもどの L でも残る。

参考数（probe12 の記録だけ。台本は本下書きと一緒に置いた
`w308_kn_continuity_ref.py`。n の合計が #4847 と一致することを検算済み）:

| 組 | n（今の定義） | L>=2 | L>=3 | L>=5 | L>=10 |
|---|---|---|---|---|---|
| K2 | 16,422 | 14,886（90.6%） | 14,002（85.3%） | 12,857（78.3%） | 11,603（70.7%） |
| WK | 28,184 | 27,010（95.8%） | 26,214（93.0%） | 25,376（90.0%） | 24,432（86.7%） |

区間の数と最長: K2 は区間 2,727・最長 509 ターン（長さ 1 の区間 1,536）、
WK は区間 2,157・最長 584 ターン（長さ 1 の区間 1,174）。n のある種×島は
K2 125・WK 136（全 400）。

### 案 D: n を「倉庫の薄さ」で絞る（実害への近さ）

- 定義案: 条件 4 の島ターンでも、島の倉庫に対象の財の在庫が残っている間は
  n に数えず、在庫が薄い（例: 0、または需要の X ターン分未満）島ターンだけを
  n とする。
- 利点: 「運べなかったが困っていない」島ターンと「運べずに困った」島ターンを
  分けられる。条件 4 の実害に一番近い。
- 欠点: 今の記録に倉庫の列が無い（probe13 の panel にも無い）ので、次の probe
  で記録の追加が必須。「薄さ」の定義（どの財・何ターン分）は新しい決め事で、
  置き方で n が大きく動く。候補の中で一番手間が大きい。

### 案 E: kn の目盛りを細かくする（GRID 拡張・連続値化）

- 定義案: GRID の右端を伸ばす（例: 5.0・10.0）・刻みを細かくする、または
  二分探索を連続値（細かい刻み）にして kn を連続値で記録する。
- 利点: 3.0 の山がほぐれて分布の形が見える。kn >= 1 の判定は変わらないので、
  今の n の数（上限 3.0 で数える限り）は動かない。
- 欠点: #5078 の読みどおり、**n が 1 財で立つ作り自体は直らない**。診断には
  良いが、運用の物差しの直しにはならない。過去の記録にも適用できない。

### 案 F（参考・後ろに置く）: 引き合う財の量で立てる

- 倍率 1.0 で引き合う財の需要の合計が、島の輸入需要の線（割合）以上のときだけ
  n とする、案 B の量版。定義の新規度が高く記録の追加も要るので、候補としては
  後ろに置く。

## 3. 既存の数え直し結果への影響

- **probe12 の合否には使わない**（#5074 の決め 1）。どの案も次の測りの物差しの
  話で、条件 4 の判定の扱いは #5074 の決め 2（条件 5 と同根と読む）のまま。
- 案 C だけは過去分にも参考数を付けられる（上の表）。案 B・D・F は記録の追加が
  前提で、過去分は「財の数・倉庫は未確認」のまま残る。
- c4-split（戻った/戻っていないで分けた数え直し、#5099）の読みへの効き:
  あの集計の n は今の定義。特に、基準中央値 0 の 24 島に残った n（最終窓
  554 ターン。この 24 島で n が立った 2,031 ターンは全部 kn = 3.0 だった）は、
  案 B で「1 財か複数財か」が分かると読みが変わり得る一番の見どころ。物差しが
  変われば、あの検算（戻った島で n が消えたか）は次の測りでやり直しになる。

## 4. 移行の手間

- 案 A: probe 台本の小さな変更（数える版の判定 + 記録列の追加）。集計側は列が
  増えるだけ。次の W 系 probe にそのまま載せられる。
- 案 B・F: 案 A の記録が前提で、変更は集計の定義だけ。
- 案 C: 集計側だけの変更。今すぐでも試せる（参考数は出した）。
- 案 D: probe に倉庫の記録を追加（島の `warehouse` の読み取り）+ 集計の定義
  変更。一番大きい。
- 案 E: probe の GRID/探索の変更のみ。

## 5. 下書きとしての推し（会議への提案）

1. 次の W 系 probe には案 A（素の最小ログ: 倍率 1.0 で引き合う財の数・段ごとの
   財の数・倉庫の薄さの材料）を入れる。これが他の全部の前提。
2. n の立て方の軸は案 B（引き合う財の数）にし、案 C（続いたターン数）は
   重ねる条件として併記する。案 C 単独では効きが弱いことは参考数のとおり。
   案 D は倉庫の記録が取れてから別途。
3. 線の値（K 個・L ターン）は、案 A の記録で分布を見てから、**次の測りの前に**
   会議で固定する。案 E は診断用に留め、運用の物差しにはしない。
