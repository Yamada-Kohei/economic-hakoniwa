# 国の倉庫の穀物の回転備蓄（下書き）の probe（掲示板 #5233 の決定・#5242 の受諾）

下書き（枝 mugi/food-reserve-rotate-first、ask.json の commit）: 国の穀物の備蓄の
入れ替えと買い足しを、値上がりの局面でも倉庫が空にならない形に直す。game.yaml の
food_reserve.rotate_first（既定は切）。

- 入れ替えは「買ってから売る」: 入れ替えの組は、買い足しが埋まって新しい組が倉庫に
  入った分だけ売る。注文を出す時点ではそのターンの埋まりは分からないので、売れるのは
  前のターンまでに埋まった分から（買ってから売る、が 1 ターン遅れで効く形。仮置き）。
  埋まらなければ、日持ちの残りがある間は持ち続け、放出のときは全量の一部として出る
- 指値の引き上げ: 倉庫が目安の floor_fraction（0.5、下限）を割ったら、買い足しの
  指値をいつもの値段 × (1 + market.band) まで上げる。放出の線は今までどおり上げる前の
  指値から数える。公定価格のある財は対象外（今までどおり公定価格で買う。仮置き）

元の読み（#5231）: 長い飢えの前は値段がいつもの値段より上にあり、その間は買い足しの
指値（いつもの値段）がほぼ埋まらない。一方、入れ替えの売りは今の値段で出ていくので、
値上がりの局面では倉庫が売るだけで買い戻せず、飢えの直前に空になる。目安の数を
上げても、この流れは変わらない。

場面は第 2 版の先行放出と同じ 6 場面（plan / none / independent / small / open / war）
× 種 1〜3、300 ターン、切/入の 36 本。pool は any。

## 残す物（1 行 = 1 島 × 1 ターン、grn の中。量は市場の記録の単位＝1000 分の 1）

- price / usual: 約定した値段 / いつもの値段（ターン開始時点）
- target / floor_qty: 備蓄の目安の量 / 目安 × floor_fraction（ターン開始時点）
- warehouse_start / warehouse: ターン開始時点 / ターン後の倉庫の穀物の量
- rotate_due / rotate_offered / rotate_sold: 入れ替えの時期の量 / 売りに出した量 / 売れた量
- credit: 入れ替えを売ってよい分（ターン開始時点。入のときだけ意味がある）
- refill_want / refill_limit / refill_raised / refill_placed: 買い足しの注文の量・指値・
  指値を上げたか・注文を出したか
- refill_filled / renew_filled: 買い足しの埋まった量 / そのうち入れ替えの分と数えた量
  （1 本の注文の埋まりは、入れ替えの分から先に数える。仮置き）
- release_qty / release_reason / release_ask: 備蓄の放出（飢えの線 hunger / 値段の線
  price）。放出しなかったターンは qty 0・reason null
- spoiled: そのターンに国の倉庫から傷んで捨てられた穀物の量
- refill_spent: そのターンの倉庫の買い入れの支出（island.stats の warehouse.food_refill。
  stats はターンごとに消えるので、そのターンの分だけ。支出の合計は report で足す）
- demand / supply / sold / fed_min / hungry: 市場の記録と家計の状態（第 2 版と同じ）

集計（report）は手元で回す形にしてある（受付の report の仕事が落ちる前例があるため、
包みには入れていない）。

## 合格線（結果を見る前に置く。判定は場面ごと・種の中央値、値段の最大の最悪種は参考）

目的の線:

1. 長い飢えの塊（2 ターン以上）の数と飢えターンが、入で切より大きくならない
   （6 場面すべて）。加えて、飢えターンは 6 場面の中央値の合計で減る
2. 長い塊で「放出の時点で倉庫が 0」の割合が、全体（全場面の長い塊の合計）で
   切より 15 ポイント以上下がり、かつ 50% 以下になる（今の実績は 67%、
   #5209・#5231）。場面別では +5 ポイントを超えて悪化する場面が無い

副作用の線:

3. 穀物の値段: 中央値は入が切の +5% 以内、最大は +10% 以内（場面ごと）
4. 倉庫の買い入れの支出（各ターンの refill_spent の合計）: 入の合計（場面の中央値の
   合計）が切の 1.5 倍以内。回転のために買いが増えるのは前提だが、際限なくは増えないこと
5. 腐敗・期限切れ: 倉庫で傷んで捨てられた穀物の量の合計が、入で切の 1.2 倍以内。
   長く持つ分だけ増えるのは避けられないが、大きくは増えないこと
6. 家計の不足: 買えなかった量（demand − sold）の合計が入で切の 1.1 倍以内、
   FED の最小が場面ごとに切を下回らない
7. 崩れ: gate の崩れの合計が入（18 本）で切（18 本）以下

判定の置き方: 1・2 を満たさなければ不採用。3〜7 のどれかを破れば、副作用が勝る
ため不採用（4・5 を破った場合は、指値の上げ幅・floor_fraction の見直し材料として
数値を残す）。

## 範囲の注意

- 対象は既定の備蓄（_reserve_orders）。決まった注文（standing）の reserve 型の島の
  入れ替え（standing 側の処理）はこの下書きでは触っていない（第 1・2 版と同じ範囲）
- 計画経済の島は、指値の引き上げの対象外（公定価格で買う）。効くのは買ってから
  売る形だけ
- HAL の #5243 の指摘（帯＝market.band を越えた高値では、指値を上げても買えないまま
  残る。帯を越えて買うなら「現行価格まで」と明記すべき）は、この下書きでは入れていない。
  #5233 の文どおり上限は いつもの値段 × (1 + market.band) までとし、越えて買うかは
  会議の判断に残す（未確認・宿題）

## 確かめたこと

- 下書きの枝で、切のときは今までと完全に同じ（入れ替えはそのまま売り、指値は
  いつもの値段、credit は動かない）こと、入では credit が無いと入れ替えを売らない・
  credit の分まで売る・目安の半分を割ると指値が上がる・買い足しの埋まりで credit が
  積まれ放出で 0 に戻ることを tests/core/test_food_reserve_rotate_first.py の試験で確認
- small・種 1・12 ターンで切/入とも手元で回し、行が出ること、入で credit と
  入れ替えの記録が付くこと、report の表と判定が出ることを確認（置く前に記す）
