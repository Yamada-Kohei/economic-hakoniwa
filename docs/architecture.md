# 全体の構成

```
ブラウザ（server/static, server/templates）
   ↓ HTML と JSON API
Django（server/）……保存・アカウント・命令の受付・ターン更新の実行
   ↓ 状態を渡して計算させる
コア（hakoniwa_core/）……ルール本体。Django も DB も知らない
   ↓ 読む
定義データ（packs/、schemas/、game.yaml）
```

| `ledger.py` | お金の帳簿（複式の仕訳）。お金はここを通してだけ動き、毎ターン4つの確かめをする |
| `market/` | 板寄せ（財の市場と電力で使う） |

| `politics.py` | 政治の状態（フェーズ3-4）: 政情とその段階、体制の特色（`regimes.yaml` の `traits`）、報道と集会の扱い、首都の建物、建て替えの資材。段と命令は `modules/politics`（政情・選挙と議会の採決・デモと暴動・混乱期間・体制の変更）と `modules/plan`（公定価格・重点産業） |
| `diplomacy/` | 宣戦・条約・戦争の状態（フェーズ4-1）: 戦争（`war.py`）・条約（`treaties.py`）・条項の種類（`clauses.py`）・経済の条項（貿易圏・契約・固定相場・融通・援助・移民。`economic.py`）・違反が残す信用の傷（`credit.py`）。世界の状態は `world.ext["diplomacy"]`、島の違反の記録は `island.ext["diplomacy"]`。段と命令は `modules/diplomacy` |
| `units.py` | 量・お金・率の単位と丸め |
| `dates.py` | 暦: 1年のターン数（1ターン＝1か月）、ターンの年と月、年の終わり（年に1度の処理はターンが12の倍数の12月）。世界の暦は `game.yaml` の `calendar`。文面は `log.py` の `format_turn` |
| `turn/` | 段の進行役（`Engine`）、段に渡すもの（`StageContext`）、乱数 |
| `founding.py` | 建国: 形と地形の検査、描いた形からの自動の地形、首都と最初の施設・町・村の配置 |

| `autoplan.py` | 試験と一括シミュレーション用の「標準の計画」 |
| `gate.py` | フェーズ2・3の関門の目安と、一括シミュレーションでの確かめ |
| `orders.py` | 命令の検証（受付時と実行時の両方で使う） |
| `log.py` | ターンログの文面づくり |
| `game.py` | 設定・定義データ・モジュールをまとめて組み立てる `load_game()` |
| `simulate.py` | 画面も DB もなしで回す一括シミュレーション |
| `measure.py` | バランス調整の測り方: 場面（標準の計画・命令なし・中央銀行の独立・少ない島）ごとの一括シミュレーション、失業の内わけ、結果の比べ |

## 1回のターン更新

1. cron などが `manage.py run_turn` を呼ぶ。次の更新時刻になっていなければ何もしない。
2. 更新中の印を立てる（その後に届いた命令は次のターンに回る）。
3. DB から世界全体を `WorldState` に読み込み、写しをバックアップに取る。フェーズ1のままの島（お金の
   経済がまだない島）があれば、ここでお金と経済を始める（移し替え。`economy/start.py`）。
4. `game.yaml` の `stages:` の順に段を実行する。島ごとの段は島ごとに、全島の段（フェーズ3-1 の貿易
   `trade` と、その確かめ `trade_check`、国債 `bonds`、称号 `rankings`、国をまたぐ移民 `migration`）は
   世界全体に1度。
5. 変わったものだけを書き戻し、ターンログと統計、お金の勘定と帳簿の記録を足し、ターン番号を進める。

3〜5 は1つのトランザクションです。途中で失敗したら何も書かず、ターンも進めず、管理者にメールします。

## Django のアプリ

| アプリ | 中身 |
|---|---|
| `accounts` | 登録・ログイン。同じ接続元からの重複登録の制限（IP は秘密鍵で混ぜたハッシュで、決まった日数だけ持つ）。AI 用の鍵（`ApiKey`、`keys.py`。下の「AI 用の入り口」） |
| `world` | 世界・島・マス・施設・在庫・統計のモデル、DB とコアの変換（`repository.py`）、建国（`services.py`） |
| `economy` | お金の勘定・国債の銘柄・仕訳・約定・市場の記録・施設の帳簿のモデル（フェーズ2） |
| `orders` | 命令のモデル |
| `turns` | ターン更新、バックアップと巻き戻し、ターンログ |
| `web` | 画面と JSON API。表示の文面づくりは `display.py`（ルールの計算はしない） |
| `board` | 掲示板（読むのは誰でも、書くのは登録した人だけ。管理画面で書き込みを非表示にできる） |
| `hall` | 国際会議場（フェーズ4-1。公開の声明の表 `Statement`。誰でも読め、島を持つ人が出せる。1 つの島が 24 時間に出せる数は設定 `HAKONIWA_HALL_PER_DAY`。管理画面で非表示にできる。条約と戦争の出来事は表に持たず、当事国のターンログの `hall` の印から表示のときに作る） |
| `country` | 国の公開ページ（フェーズ4-1。国旗 `Flag`（検査した PNG。`png.py`）・紹介文と紀年の選び `Profile`・来訪者の一言 `Note`。どれも管理画面で非表示にできる。国ごとの日付の書き方は `services.py`。中身の組み立ては `server/web/country.py`） |
| `letters` | 国どうしの手紙（画面では「外交」の「公電」。非公開。読めるのは差出人と宛先の島の持ち主だけ。送るとすぐ届く。1 つの島が 24 時間に送れる数は設定 `HAKONIWA_LETTERS_PER_DAY`。管理画面で非表示にできる） |

DB の表は、マス（`Tile`）・施設（`Facility`）・在庫（`Stock`、国の倉庫は施設なし。作られたターンごとの行）・
統計（`StatRecord`、ターンごとの人口・生産量・GDP・物価など。島・指標・ターンの索引で、指標ごとの系列を引く）です。島と施設の経済の状態と政策は、それぞれの
`economy`・`policy` の JSON の欄に入ります。書き戻しは変わった行だけで、在庫だけは島ごとに消して書き直します。
フェーズ3-1 の貿易の状態は表を足さず、世界の `ext`（貿易圏・契約・運ぶ途中の荷）と島の `ext`（レート・
外貨の持ち高・圏と契約の見え方）の JSON に入ります。管理画面の「休止中」の印は、読み込むときに島の
`ext["inactive"]` に写します（貿易圏の代表の引き継ぎで使う）。

お金は `economy` アプリの表に入ります。勘定（`Account`、名前と残高）と国債の銘柄（`Bond`）は毎ターン島ごとに
書き直し、仕訳（`JournalEntry`）・約定（`Trade`）・施設の帳簿（`FacilityBook`）は `game.yaml` の
`records.*_turns` のターン数だけ残して古いものを消します。市場の記録（`MarketRecord`、財ごとの値段と売買量）は
消しません。巻き戻すと、戻した先より後の記録を消します。

巻き戻しは世界全体を同じ時点にそろえます。戻した先より後に建国した島は消さずに、建国したときの姿（その島が
入ったいちばん古いバックアップ、なければ今の姿）に戻し、戻したターンに建国したことにします。戻した先より後の
更新で実行した命令は待ちに戻します。書く前に帳簿と島をまたぐお金・荷を確かめ、合わなければ何も変えません。

画面の JavaScript は `server/static/js/` にあり、ビルドなしの ES モジュールです。
`map/` が俯瞰図（`overlays/` に重ねて表示する情報を1ファイルずつ足せる）、`island/` がマスの情報と命令の列、
`founding/` が建国の画面です。`chart/` は外部のライブラリを使わない小さな折れ線グラフ、`reports/` は
経済・市場・施設・財政・金融・貿易・為替・政治と計画の画面です（命令の欄は `island/` の命令の列をそのまま使い、今の列の後ろに
足す）。他国の人にもこれらの画面は見せますが、施設の帳簿・約定の相手・銀行ごとの中身・契約・商社・船団・外貨の持ち高・
命令の欄は島の持ち主だけです。貿易と為替の画面のデータは `server/web/trade.py` が島と世界の `ext["trade"]` から、政治と計画の画面のデータは
`server/web/politics.py` が島の `ext["politics"]`・`ext["plan"]` から組み立てます。

ある時点のターンは、テンプレートでは `{{ turn|turn_date }}`（`server/web/templatetags/calendar_tags.py`）、JavaScript では `calendar.js` の `turnDate` で「箱庭暦32年11月（ターン 383）」と書きます（暦の設定は `base.html` が
ページに埋め込む）。

## AI 用の入り口

AI（Claude や ChatGPT など）が人と同じ決まりで遊ぶための入り口です。人の画面は変えず、同じ情報を AI の読みやすい形で出します。

- **AI 用の鍵**（`server/accounts/keys.py`、表 `ApiKey`）: アカウントの画面で作り、AI に渡す。`/api/` と `/mcp` だけで、
  `Authorization: Bearer <鍵>` をそのアカウントのログインとして扱う（`KeyMiddleware`。ブラウザが勝手に付けないので CSRF の印は要らない）。
  鍵そのものは作ったときに1度だけ見せ、DB には SHA-256 のハッシュだけを置く。1つの鍵で呼べる回数は1分に `HAKONIWA_AI_CALLS_PER_MINUTE`
  回まで（既定 60。Django のキャッシュで数える）。
- **AI の国の印**: 取り消していない鍵を持つアカウントの島と、鍵を最後に使ってから 12 ターン（`MARK_TURNS`）の間の島には、
  国の一覧（`/`）と国の画面の見出しに「AI」の印を出す（`web/ai_mark.html`。`/api/world` の `ai` も）。持ち主は消せない。
- **国の要約と差分**（`server/web/overview.py`）: 上の `summary`・`changes`。画面と同じ値を集めて短くしただけで、新しい計算や先の見込みは出さない。
- **MCP のつなぎ先**（`POST /mcp`、`server/web/mcp.py`）: MCP の Streamable HTTP で、状態を持たず、1つの POST に1つの JSON で答える
  （GET の SSE とセッションは使わないので 405）。鍵がなければ 401。道具（要約・差分・ターンログ・地図・マス・統計・画面の中身・定義・
  命令の確かめと置き換え・世界・順位・公電・掲示板・建国・手引き・API の GET）は、どれもサーバーの中で上の JSON API のビューを同じ
  アカウントで呼ぶだけなので、見られるものと出せる命令は人と同じ。stdio でしかつなげない AI のために、`tools/playtest/hk.py mcp` が
  標準入力の JSON-RPC を `/mcp` に送る。
- **人と同じにそろえる決まり**: 命令・画面・画面に出す値・地図の重ね表示を足したり変えたりしたら、同じ PR で JSON API・MCP の道具・
  国の要約と差分も合わせる。`tests/server/test_ai_parity.py` が次を確かめる。
  - 人が見る画面（URL の名前）が、すべて `mcp.SCREENS`（同じ中身を読む道具）か `mcp.NOT_FOR_AI`（アカウントの画面）に載っている。
  - 島の画面・統計の画面・ターンログでテンプレートに渡す値が、`summary`・`report`・`turn_log` の答えのどこかに同じ値である
    （統計の表は統計の名前で比べる。形の違うものは試験の `ALIASES`、見せ方だけの値は `PRESENTATION`）。
  - 画面とスクリプトで出す命令が、すべて `defs(section="orders")` にある。
  - 地図の重ね表示（`static/js/map/overlays/`）が、すべて `map` の `overlay` で文字の地図になる。
