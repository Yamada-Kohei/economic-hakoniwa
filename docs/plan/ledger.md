## 決まり

1. **書くのはコーディネーター 1 人。** スレッドは「束の番号・PR・日付・始めた／済んだ」の形でコーディネーターに知らせる（共有フォルダは後から書いた方が勝つため）。
2. 束の番号（計算の列 C1〜、並べる列 P1〜）は変えない。足すときは末尾の番号を使う。
3. 束が済んだら「文書の直し待ち（PR 番号・日付）」と書き、W を 14-plan の「片付けた物」へ移す PR が入ってから「済み」にする。片付ける前に本人に一言聞く。
4. 台帳は PR と同時には直せない。PR に束の番号と台帳の変える所を書き、コーディネーターが直すまでは「台帳の直し待ち」。束の番号は PR の題名と報告にも入れる。
5. 書き換えるたびに控えを plan/old/ledger-日付.md に残す。
6. 計算の列は X870 で 1 束 1 回の full が目安。失敗・前提の変化・基準が足りないときは測りを足してよい。束を分けたり順を変えたりしたら、ここに書く。
7. 「読むだけ」で決めるときは、読んだ full のコミット・場面・乱数の種・設定を書き残す。
8. 速くする・片付けの直しは結果が同じことを確かめてから取り込む（独立した束、測るコミットは固める）。次の束が測るコードと重ならない所だけにする。
9. 1 束は 1 回の full で原因が切れる大きさにする。「済み」は束の全部が済んだときだけ。
10. 並べる列は、進んでいる計算の列の束が触るコードには入らない。
11. 「読むだけ」は、読む量をその後の PR が触っていないときだけ。
12. 新しい後回しは、まずどの根か・どの束かを見て、束に足す（新しい束は本人に一言聞いてから）。
13. **足すときの受け口は plan/inbox.md の 1 か所**（2026-11-17）。スレッドもコーディネーターも、新しい後回しは inbox.md に決まった書式の 1 行で書く。番号は点検の台本の「次に使える番号」を使う（同じ番号を二人が使わない）。遊び手の要望で本人の判断待ちの物は plan/player-requests.md に書き、本人が OK したら inbox.md へ移す。
14. コーディネーターは毎ターンの点検で `python3 -I /mnt/project-files/plan/tools/ledger_check.py <リポジトリ>` を回し、inbox.md の行を 14-plan（PR）と索引へ移す。重なる W は足すときに既にある W へまとめる。「そろっている」と出れば定期の整理は要らない。日付の書き足しは台帳の本文に書かず、束の中身か「今の状態」を直す（記録は plan/old/ へ）。

### 権利で確かめる点（ST-1 の中身。法律の判断はせず、確かめる先と論点まで）

1. **名前「箱庭諸国」と元の「箱庭諸島」系との近さ・商標**: 確かめる先は、特許情報プラットフォーム（J-PlatPat）で「箱庭諸島」「箱庭諸国」などの商標登録の有無、元の箱庭諸島の権利者の公開情報（配布の条件・商標の表示）。論点は、登録商標があるか、名前がどれくらい近いか（混同のおそれ）、ジャンルの普通の呼び名として使われてきた経緯があるか。
2. **元の作品から引き継いだ名前・文**: リポジトリの README に「既存の箱庭諸国のコードは使わず、新しく書いています」と明記があり、コードの写しは無い建て付け。ただし賞の名前（繁栄賞・平和賞・災難賞・ターン杯など、docs/design/13-decisions.md）など、元の箱庭諸島の名前を引き継いだ物がある。論点は、名前・用語の引き継ぎがどこまで許されるか（元の作品の利用条件・配布条件が確かめる先）。リポジトリ内に元のコード・絵・文の写しが残っていないかは、足すときに改めて全体を点検する（license-care のような記録は今のリポジトリには無い）。
3. **外の部品（ライブラリ）の許諾と、売る物に入れてよいか**: 出典とライセンスは THIRD_PARTY.md に記録済み。Django（BSD-3-Clause）・PyYAML（MIT）・jsonschema（MIT）・gunicorn（MIT）は同梱の条件が軽い部類。論点になるのは psycopg（LGPL-3.0、PostgreSQL 用・任意）と pywebpush（MPL-2.0、通知用・任意）で、一人用ではそもそも両方とも外す選択肢がある（DB は SQLite、通知は不要）。確かめる先は各ライセンスの本文と、Steam の配布条件（同梱する実行ファイルの形で条件が変わるか）。
4. **フォント**: 今は OS のフォントの名前を指定するだけで、フォントのファイル自体は同梱していない。一人用でフォントを同梱する場合は、そのフォントの再配布・商用の条件が確かめる先。
5. **音**: 今は音の素材が無い。足す場合は、出所とライセンスを THIRD_PARTY.md に記録する決まり（AGENTS.md）に従い、出典の分からない物は使わない。
6. **絵**: マップの絵は全部リポジトリの中で生成し、THIRD_PARTY.md に作った人・道具・MIT ライセンスを記録済み。論点は、AI で作った絵についての生成道具の利用条件（売る物に使ってよいか）が確かめる先。
7. **ライセンス表示の形**: リポジトリに LICENSE ファイルは無く、pyproject.toml の `license = "MIT"` の宣言だけ。売る物に入れる著作権表示・ライセンス表示の形（自作分と外部の部品の分）が確かめる先。
8. **名前を変える場合の候補の考え方**（候補そのものは本人が決める）: (a) 経済・経営の要素が伝わる名前、(b) 既存のゲームの名前・登録商標と被らない（J-PlatPat と Steam の中での検索が確かめる先）、(c) 対象の言語（英・中・韓・露・独）で変な意味にならず読める、(d) ストアの名前とドメインの空き。
