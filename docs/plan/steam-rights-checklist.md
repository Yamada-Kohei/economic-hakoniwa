## この文書の決まり

- **法律の判断はしません。** ここに書くのは「何を」「どこで」「どうやって」
  確かめるかと、「何が分かれば十分か」までです。「使ってよい／だめ」の
  最終判断は、迷った時点で専門家に聞く話として残します。
- 困ったときの聞き先: **INPIT（工業所有権情報・研修館）の知財総合支援窓口**
  は無料で日本語で相談できます（商標・著作権などの入り口相談。全国に窓口が
  あり、電話でも聞けます）。深い判断は弁理士・弁護士の仕事です。
- 調べた結果は、そのつどメモに残してください（確認した日付・
  出どころの名前と版・該当する節や箇所・調べた言葉・分かったこと）。
  版と節まで残すのは、出どころの文書や配布の構成が変わったときに、
  どこを見直せばいいか分かるようにするためです。あとで会議や専門家に
  見せる材料にもなります。
- 英語のページが必要な所には、その旨と対処を書きました。

## 1. 名前「箱庭諸国」が商標とぶつからないか

- **何を**: 「箱庭諸島」「箱庭諸国」という名前が、他人の商標（名前の
  独占権）として登録されていないか。
- **どこで**: **J-PlatPat（特許情報プラットフォーム）**。特許庁の外郭団体
  INPIT が運営する公式の検索サイトで、無料・会員登録なし・日本語です。
  https://www.j-platpat.inpit.go.jp/
- **手順**:
  1. トップページで「商標」の検索（商標検索）を開く。
  2. 検索の欄に「箱庭諸島」を入れて検索する。同じように「箱庭諸国」、
     読みの「ハコニワショトウ」「ハコニワショコク」でも検索する。
  3. ヒットしたら、その行を開いて「権利者（誰の商標か）」「区分」
     「状態（登録済みか、出願中か）」を見る。ゲームに関係するのは
     第 9 類（プログラム・ダウンロードされるゲーム）、第 41 類
     （オンラインゲームの提供）、第 42 類あたりです。
- **何が分かれば十分か**: 4 つの言葉それぞれについて「ヒットなし」か、
  ヒットした場合は「誰の・どの区分の・登録か出願か」がメモできていること。
- **つまずきやすい点**: 商標は「名前 × 区分」の組で押さえられます。
  関係ない区分（例: 食品）の同名は、直ちに問題とは限りません。判断に
  迷うヒットがあったら、その画面の控えを持って INPIT の窓口へ。

## 2. 元の「箱庭諸島」から引き継いだ名前・文

- **何を**: (a) 元の箱庭諸島の配布条件・利用条件に、名前や用語の
  引き継ぎと、商用利用（売ること）について何と書いてあるか。
  (b) 今のゲームの中に、元のコード・絵・文の写しが残っていないか。
- **どこで**:
  - (a) 元の箱庭諸島の**公式の配布ページと、配布物に同梱の説明文**
    （readme など）。Web 検索で「箱庭諸島」を探し、配布元のページの
    「利用条件」「著作権」「転載」などの文を読みます。昔のページが
    消えているときは Wayback Machine（web.archive.org、英語の画面
    ですが検索窓にアドレスを入れるだけです）で過去の姿が見られる
    ことがあります。
  - (b) このリポジトリの中です。README に「既存の箱庭諸国のコードは
    使わず、新しく書いています」と明記があります。引き継いだ名前の
    例は賞の名前で、docs/design/13-decisions.md に「元の箱庭諸島の賞
    （繁栄賞・超繁栄賞・究極繁栄賞・平和賞・災難賞・ターン杯）に
    平穏賞を足した」と記録があります。
- **手順**: 配布条件の文を手元に保存し、「名前・用語を使ってよいか」
  「商用利用はよいか」の 2 点について書いてある文を抜き出す。
  書いていない点は「書いていない」とメモする（= 判断は会議・専門家へ）。
  抜き出した文には、出どころ（ページやファイルの名前）と、確認した
  日付も一緒に残してください。
- **何が分かれば十分か**: 配布条件の文が手元にあり、上の 2 点について
  「書いてある内容」または「書いていないこと」がはっきりしていること。

## 3. 外の部品（ライブラリ）のライセンス

この項目は、確かめる順序が大事です（掲示板 #6504・#6507 で合意した
順序）。

1. **まず、候補ビルドに同梱される部品の一覧と THIRD_PARTY.md を
   突き合わせる。**
2. **ライセンスを確かめるのは、実際に同梱される部品だけにする。**
3. **「外す／残す」の判断は、確かめ終わってからにする。**

- **何を**: 売る物（候補ビルド）に実際に同梱される外部のプログラム
  部品と、それぞれのライセンス（使う条件の文書）で「売る物に入れて
  よいか」「何を表示しなければならないか」。
- **どこで**: 部品の一覧の正はこのリポジトリの **THIRD_PARTY.md**
  です（部品ごとに用途・ライセンス名・出典のアドレスが表に
  なっています）。各ライセンスの本文は、出典先（公式サイト・
  GitHub・PyPI）の LICENSE ファイルで読みます。
- **手順**:
  1. 候補ビルドができたら、その配布物に実際に入っている部品の
     一覧を取り、THIRD_PARTY.md の表と 1 行ずつ突き合わせます。
     **配布物に入っていない部品は、その時点で確かめる対象から
     外れます。** 候補ビルドはまだ無いので、この突き合わせは
     ビルドができた時点の作業です。
  2. 同梱される部品だけ、出典先のライセンス本文で「商用・同梱の
     可否」と「表示の条件」を確認し、1 行ずつメモします。メモには、
     根拠にした資料の**版・確認した日付・該当する節や箇所**も
     一緒に残してください（配布の構成が変わったときに、どこを
     見直せばいいか分かるようにするためです）。
  3. 「外す／残す」の判断は、同梱の有無と表示の要否が分かって
     からにします。
- **今の状態**: Django（BSD-3-Clause）、PyYAML・jsonschema・gunicorn
  （MIT）は、表示などの条件が軽い部類です。重い条件が付きやすいのは
  **psycopg（LGPL-3.0、データベース PostgreSQL 用・任意）** と
  **pywebpush（MPL-2.0、通知用・任意）** の 2 つです。一人用では
  データベースは SQLite で足り、通知も要らないので、この 2 つは
  外す選択肢があります。ただし、**外すかどうかは、まず候補ビルドに
  実際に入っているかを確かめてから決めます**（入っていなければ、
  確かめる対象から自然に外れます）。
- **Steam 側の配布条件**: Steamworks のドキュメント
  （partner.steamgames.com、英語）ですが、これは出品の手続きの
  ときに読む物で、今すぐ全部を読む必要はありません。
- **何が分かれば十分か**: 候補ビルドの同梱一覧と THIRD_PARTY.md の
  突き合わせが終わっていて、同梱される部品の全行について可否と
  表示の条件が、根拠の版・日付・節と一緒にメモできていて、その上で
  psycopg と pywebpush の扱い（外す／残す）が決まっていること。
- **英語について**: ライセンス本文は英語です。ライセンス名で日本語の
  解説を検索すれば当たりは付きますが、最終の判断材料は本文か
  専門家の確認です。

## 4. フォント

- **何を**: 売る物にフォントのファイルを同梱する場合、そのフォントの
  再配布・商用の条件。
- **今の状態**: フォントは同梱していません（OS のフォントの名前を
  指定するだけ）。**同梱しないなら、この項目で確かめることは
  ありません。**
- **どこで**（同梱したくなったら）: そのフォントの配布ページと、
  フォントに付いてくるライセンス文（LICENSE や OFL.txt という
  ファイル）。Google Fonts で配るフォントは、フォントごとのページに
  ライセンスが表示されます（SIL Open Font License の物が多い）。
- **何が分かれば十分か**: 使うフォントごとに「売る物に入れてよい」と
  ライセンス文で追えていること。

## 5. 音

- **何を**: 音の素材を足す場合、その出所とライセンス。
- **今の状態**: 音の素材はありません。**足さないなら確かめることは
  ありません。**
- **どこで**（足すとき）: 素材の配布ページの利用規約です。この
  リポジトリの決まり（AGENTS.md）で、外部の素材を足したら同じ変更で
  THIRD_PARTY.md に出典とライセンスを書くことになっています。
  出典の分からない物は使いません。
- **何が分かれば十分か**: 使った音すべてが THIRD_PARTY.md に載って
  いて、出所が追えること。

## 6. 絵（AI で作った絵）

- **何を**: マップの絵を作った道具の利用規約で、「作った物を売る物に
  使ってよいか」。
- **今の状態**: マップの絵は全部このリポジトリの中で AI で生成し、
  THIRD_PARTY.md の絵の表に、作った人・道具・ライセンス（MIT）を
  記録済みです。確かめる先は絵そのものではなく**道具の規約**です。
- **どこで**: THIRD_PARTY.md の絵の表で道具名を確認し、その道具の
  運営会社の利用規約のページで「生成物の権利」「商用利用」の節を
  読みます（道具は Claude・OpenAI Codex など。規約は英語のページが
  基本ですが、日本語版の規約を用意している会社もあります）。
- **何が分かれば十分か**: 使った道具ごとに「生成物を商用に使える」と
  規約の文で追えていること。規約は変わることがあるので、確認した
  日付と、読んだ節の名前もメモに残してください。

## 7. ライセンス表示の形

- **何を**: 売る物の中に、自作分の著作権表示とライセンス文
  （MIT）と、外部の部品の著作権表示・ライセンス文を、どういう形で
  入れるか。**対象になる外部の部品は、第 3 項で候補ビルドへの
  同梱が分かった物だけです**（同梱されない部品の表示は要りません）。
- **今の状態**: リポジトリに LICENSE ファイルは無く、pyproject.toml の
  `license = "MIT"` の宣言だけです。
- **どこで**: 各部品のライセンス本文の「表示の条件」が根拠です
  （多くのライセンスは、著作権表示とライセンス文のコピーを一緒に
  入れることを条件にしています）。根拠にしたライセンス本文の版・
  確認した日付・該当する節は、第 3 項のメモに残っています。形の
  実例は、外部の部品を使う他のゲームのライセンス表示画面や
  同梱ファイルです。
- **何が分かれば十分か**: 「何の文を、どこに（ゲーム内の画面か、
  同梱のテキストファイルか）入れるか」と、LICENSE ファイルを置くか
  どうかが決まっていること。**実際に表示を作る作業はこの項目では
  なく、別の作業です。**

## 8. 名前を変える場合の候補の確かめ方

候補そのものは本人が決めます。ここは確かめ方だけです。

- **既存の名前・商標と被らないか**: 第 1 項と同じ J-PlatPat の手順に
  加えて、**Steam ストア内での検索**（store.steampowered.com、
  日本語の画面で候補の名前を検索）と、普通の Web 検索で同名の
  ゲームがないかを見ます。
- **対象の言語で変な意味にならないか**: 対象は英・中・韓・露・独です。
  辞書サイトや翻訳（Google 翻訳など）で意味と読みの当たりを付けます。
  ただし翻訳だけでは断定できないので、最終的にはその言語が分かる
  人に見てもらうのが確実です。
- **ドメインの空き**: お名前.com などドメイン屋の検索（日本語の画面）
  で、候補の名前の .com などが取れるかを見ます。
- **何が分かれば十分か**: 候補ごとに、商標・ストア・Web の 3 つの
  検索結果と、言語の当たり、ドメインの空きがメモできていること。

## 残る判断（この文書では決めないこと）

- 第 1・2 項で「迷うヒット」「条件に書いていない点」が出たら、
  INPIT の知財総合支援窓口か弁理士に、メモと画面の控えを持って
  相談するのが最終判断の先です。
- 名前そのもの（「箱庭諸国」のまま行くか、変えるか、変えるなら
  何にするか）は本人の判断です。
