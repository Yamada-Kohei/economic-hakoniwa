# 規模の測定

目標: 既定の 50 島で、1回のターン更新を 5 分以内に収める。

## 測り方

```sh
python manage.py create_sample_world --islands 50 --seed 1
python manage.py run_turn --force      # かかった秒数が出る
python -m hakoniwa_core.simulate --islands 50 --turns 300 --autoplan   # DB なしの計算だけ
```

## フェーズ2-1の結果（2026-10-12、開発用のクラウド環境）

段は命令・予算・雇用・生産と電力・建設・賃金・市場・銀行・国債・決算・人口・町・災害・記録の14です。

| 場合 | SQLite |
|---|---|
| 建国直後の 50 島（施設 約 1,100） | 1.9〜2.3 秒 |
| 標準の計画で 200 ターン育てた世界（施設 1,678） | 3.0〜3.2 秒 |
| コアの計算だけ（標準の計画で 300 ターン、1ターン平均 / 最大） | 0.61 秒 / 0.96 秒 |

一番時間を使うのは市場の段です（財ごとの板寄せと、家計の注文）。建国直後の 50 島で、1ターンに
仕訳 約 6,700 行・約定 約 340 行・市場の記録 約 390 行・施設の帳簿 約 620 行を書きます。
仕訳と約定は 24 ターン分だけ残して消すので、表は一定の大きさで止まります。
5 分の目標に対して、まだ十分に小さいままです。

## フェーズ1の結果（2026-10-12、開発用のクラウド環境、1コア相当）

50 島 × 32 × 32 = 51,200 マス。段は命令・雇用・生産・建設・配分・人口・町・災害・記録の9つです。

| 場合 | SQLite | PostgreSQL 16 |
|---|---|---|
| 建国直後から 60 ターン（命令なし、施設 約 1,100） | 1.6〜2.2 秒 | 1.7〜2.0 秒 |
| 標準の計画で 200 ターン育てた世界（施設 3,600、人口約 49 万） | 1.9〜2.1 秒 | 2.2〜2.3 秒 |
| コアの計算だけ（標準の計画で 300 ターン、1ターン平均 / 最大） | 0.31 秒 / 0.57 秒 | - |

300 ターン目には施設 4,253、人口約 61 万になり、計算で一番時間を使うのは人口の段でした。
5 分の目標に対して十分に小さいままです。

育てた世界は、コアで 200 ターン回した状態を DB に入れてから `run_turn` で測りました
（プレイヤーの命令がない DB の世界では工場が増えないため）。

## フェーズ0の結果

段が「命令の実行」だけの、空の島の世界です。

| 場合 | SQLite | PostgreSQL 16 |
|---|---|---|
| 何も変わらないターン（読み込み・バックアップ・書き戻し） | 0.6〜0.8 秒 | 0.8〜0.9 秒 |
| 全マスが変わるターン（最悪の書き戻し） | 1.2〜1.6 秒 | 3.0〜3.2 秒 |

### 分かったこと

- Django の `bulk_update` は 5 万行で 20 秒以上かかりました（式の組み立てが重い）。
  `server/world/bulk.py` の `update_rows`（同じ UPDATE 文を executemany で送る）に替えて 3 秒になりました。
- 施設は変わった行だけを書き戻し、在庫は島ごとに消して書き直しています。どちらも 1 ターン 2 秒前後に収まっています。
