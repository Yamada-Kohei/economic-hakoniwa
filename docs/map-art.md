# マップの絵の仕様

島の俯瞰図に使う絵（スプライト）の決まりです。絵は人でも AI（Codex など）でも描けるように、
ここに書いたことだけで作れて、ここに書いたことで見直せるようにしています。
絵がないものは、これまでどおり色付きのひし形と箱で描くので、少しずつ足していけます。

## しくみ

- 絵は `server/static/themes/<テーマ>/sprites/` の下に置き、同じテーマの `theme.yaml` の `sprites` に
  「名前 → ファイル」で並べます。いまのテーマは `default` だけです（`game.yaml` の `theme`）。
- 描くのは `server/static/js/map/renderer.js` で、絵の読み込みは `sprites.js` です。
  `sprites` に載っていない名前、読み込めなかった絵は、色の箱で描きます。
- 小さな地図（右下の全体図）は今後も `theme.yaml` の色で描きます。絵の色合いをその色に近づけてください。

```yaml
# server/static/themes/default/theme.yaml
sprite_scale: 1
sprites:
  terrain/plain: sprites/terrain/plain.svg
  facility/steel_mill: sprites/facility/steel_mill.svg
  housing/city: {file: sprites/housing/city.svg, anchor: [32, 96]}   # 基準点を変えるときだけ
  facility/bank: {file: sprites/facility/bank.png, scale: 0.5}       # 2 倍で描いた PNG
```

海沿いの施設（定義データで `coastal: true`。いまは漁港・港・造船所）は、隣の海のある向きごとに絵を分けます。
名前のままの絵は海が右下（マスの x + 1）、`@sw` は左下（y + 1）、`@ne` は右上（y − 1）、`@nw` は左上（x − 1）です
（例 `facility/port@sw`）。地図は手前（右下・左下）の海を先に選び、その向きの絵がなければ名前のままの絵で描きます。
海が手前の絵は、海側の縁の水面を海の高さ（平地の 1 段 = 8 ピクセル下）まで下げ、陸の側に岸壁を立てて、
海のマスと段差なくつなげます。絵が下の頂点より下に伸びるので、`anchor` で基準点を合わせます。海が奥の絵は、
陸の縁に隠れて岸壁が見えないので、水面を陸の高さに描きます。船は水の上に置き、陸に載せません。

施設はこれからも増えます（フェーズ2-2 以降）。新しい施設の絵は、その施設が定義データに入ってから足します。
いまある名前は、見本ページ（下）の上に「絵がないもの」として出ます。

## 大きさと位置

| 項目 | 決まり |
|---|---|
| マス | ひし形。幅 64・高さ 32 ピクセル（`theme.yaml` の `tile_width`・`tile_height`）。縦横 2:1 |
| 地面の段 | 1 段 8 ピクセル（`step_height`）。地形の側面（崖）はコードが色で描く |
| 施設の段 | 1 段 10 ピクセル（`facility_unit`）。壁の高さの目安 |
| 基準点 | 絵の **下の真ん中** を、マスの上面のひし形の **下の頂点** に合わせて描く。変えるときは `anchor: [x, y]`（絵の左上からのピクセル） |
| 幅 | 地形は必ず 64（マスの幅）。施設と住宅は 64 以下にし、建物の足元はひし形の内側（8 割ほど）に収める |
| 高さ | 自由。上に伸びたぶんは奥のマスに重なって描かれる（奥から手前へ描くので、それで正しい） |
| 光 | 左上から。左の側面を明るく、右の側面を暗く（いまの箱は上面の色の 0.78 倍と 0.62 倍） |

地形の絵は、そのマスの上面（ひし形）と、そこから上に出る木や山だけを描きます。隣のマスとつながって
見えるよう、ひし形の縁ぎりぎりまで塗り、縁取りの線は付けないか、ごく薄くします。
海と浅瀬は平らなひし形です。施設のあるマスでは地形の絵は描かず、上面の色（`theme.yaml` の `terrain` の
`top`）だけを塗ります（施設の絵と木や山が重ならないように）。山に建つ施設は、岩や崖を施設の絵の中に描きます。

施設の絵の大きさの例（製鉄所、3 段）: 幅 64、高さ = 足元のひし形 32 + 壁 30 + 煙突などの飛び出し。
基準点を変えないなら、絵の一番下の行がマスの下の頂点に来ます。

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="64" height="80" viewBox="0 0 64 80">
  <!-- 左の側面・右の側面・屋根・煙突。足元のひし形の下の頂点が (32, 80) -->
  <polygon points="6,51 32,64 32,80 6,67" fill="#6b3a2e"/>
  <polygon points="58,51 32,64 32,80 58,67" fill="#552e25"/>
  <polygon points="32,38 58,51 32,64 6,51" fill="#8a4b3c"/>
  <rect x="40" y="8" width="6" height="40" fill="#444"/>
</svg>
```

## 首都の建物

首都のマスの官庁（`category: admin` の施設）は、島の体制で決まる首都の建物の組み合わせの絵で描きます。
名前は `capital/<政治の仕組みの建物>-<元首の形の建物>` で、建物は `packs/base/data/regimes.yaml` の
`capital_building` です（経済体制の軸には建物がありません）。地図の API の `capital_buildings` が、
軸の順にこの建物を返します。

| 名前 | 体制 | 絵 |
|---|---|---|
| `capital/parliament-palace` | 民主制 × 君主制 | 縦の筋の多い石の議事堂、端に時計塔 |
| `capital/parliament-presidential_office` | 民主制 × 共和制 | 白い議事堂の真ん中に高い丸屋根 |
| `capital/official_residence-palace` | 権威主義 × 君主制 | 黄色い壁の長い王宮と、前の幾何学の庭と噴水 |
| `capital/official_residence-presidential_office` | 権威主義 × 共和制 | 赤れんがの城壁と塔に囲まれた大統領府 |
| `capital/party_headquarters-palace` | 全体主義 × 君主制 | 鉛ぶきの屋根の王宮に赤い垂れ幕と赤い旗、広場の大きな金の像 |
| `capital/party_headquarters-presidential_office` | 全体主義 × 共和制 | 段々に細くなる党本部の塔と、像と旗の広場 |

- 実在の建物の雰囲気（時計塔・丸屋根・城壁・広場の像など）だけを借り、そっくりには描きません。
- 政治の仕組みを変えると首都の建物を建て替えます。建て替えが済むまでは前の体制の建物の絵のままで、
  マスの欄の「首都の建物」とそろいます。元首の形を変えたときは建て替えがないので、すぐ変わります。
- 組み合わせの絵がなければ `capital/<施設の sprite>`、それもなければ `facility/<施設の sprite>` で描きます。
- 見本ページの「首都」は、`?capital=party_headquarters-palace` のように組み合わせを選べます
  （既定は軸ごとの最初の建物）。

## 絵の描き方

- **形式は SVG を基本にします。** 拡大しても粗くならず、差分で中身が読めて、直しやすいからです。
  PNG（または WebP）も使えます。そのときは 2 倍の大きさで描き、その絵の項目に `scale: 0.5` を付けます
  （例 `facility/bank: {file: sprites/facility/bank.png, scale: 0.5}`。`anchor` は元の画像のピクセルで書きます）。
- SVG には数値の `width` と `height` を書きます（`viewBox` だけでは大きさが決まりません）。
  `<script>`、`on...` 属性、外のファイルや URL の参照、`<foreignObject>` は使えません。1 ファイル 100KB まで。
- 絵柄: 平らな塗りと少しの陰影の、すっきりした見下ろしの絵。縮小（0.25 倍）でも何の施設か形で分かるように、
  施設ごとに目立つ特徴（製鉄所の高炉と煙突、発電所の冷却塔、港の桟橋など）を 1 つ入れます。
  拡大（4 倍）しても見苦しくないこと。
- 住宅は村 → 町 → 都市 → 大都市で、建物が高く密になっていくのが分かるようにします（目安の段の高さを守る）。
- 絵の中に文字を書きません（画面は日本語以外にも訳すため）。
- 選んだマスの枠、止まっている施設の赤い印、重ね表示の色、送電線、開発禁止の斜線はコードが描くので、絵に入れません。
- 絵を生成するスクリプトを書いたときは `tools/sprites/` に置き、標準ライブラリだけで動くようにします。

## 軍事の絵（フェーズ4）の雰囲気合わせ

フェーズ4（軍事。設計は [docs/design/15-military.md](design/15-military.md)）で足す絵は、今ある絵と並べて浮かないように、次に合わせます。名前は、その絵を描ける仕組み（地図の API と描くコード）が入る回の PR で、上の「名前の一覧」に足します。それまでは描き始めません。

### 今の絵と同じにすること

- 描き方: 今の施設の絵と同じく `tools/sprites/silhouette.py` の形（箱・円柱・屋根）の組み合わせで作り、`SHAPES` に足します。手で描くときも、同じ平らな多角形・同じ色の細い縁（`stroke-width` 0.4、塗りと同じ色）・角の丸め（`stroke-linejoin="round"`）にします。
- 光と濃淡: 左上から。上面を基準に、左の側面は約 0.78 倍、右の側面は約 0.62 倍の明るさ。影の楕円や光沢、ぼかし（グラデーション）は入れません。
- 大きさ: 施設は幅 64 で、上の「大きさと位置」のとおり。壁の高さは下の表の段に合わせ、目立つ特徴を 1 つだけ上に出します。
- 色: `silhouette.py` の部品の色（`CONCRETE`・`METAL`・`IRON`・`ROOF_STEEL`・`DARK`・`COPPER`・`GLASS` など）を使い、新しい色は下の 3 つだけ足します。

| 名前 | 色 | 使う所 |
|---|---|---|
| `MILITARY` | `#7d8466`（くすんだ緑灰） | 軍の建物の壁・車両・部隊の印の地 |
| `MILITARY_DARK` | `#5c6249` | 軍の建物の屋根・戦車の車体の上 |
| `NAVY_GRAY` | `#8a96a0` | 軍艦と潜水艦の船体（輸送船の色とは分ける） |

- 赤（`RED`）と黄（`YELLOW`）は、警戒の縞やミサイルの先など、1 つの絵に小さく 1 か所までにします。軍の絵が島じゅうで目立ちすぎないためです。
- 入れないもの: 文字・数字・国旗・実在の国や軍の記章・放射能の標識（文字に近い記号のため）・爆発や炎や血。壊れたマスと戦場の印は、コードが描く印と別の絵（下）で表します。

### 部隊の印と船団

- 部隊の印は、島の俯瞰図のマスの真ん中に立てる小さな絵です。幅 28・高さ 28 ほどで、基準点は下の真ん中。マスの施設の絵の上に重なるので、輪郭を 1 段暗い色で囲み、地に紛れないようにします。
  - 歩兵: ヘルメットの兵 3 人の並び。機甲: 斜め上から見た戦車 1 両。反乱軍: 帽子と茶色の服の人 3 人（軍と見分けられること）。
  - 味方と相手、どこの国かは、コードが印の下に国の色の輪を描きます。絵は国によらず同じにします。
- 世界マップの船団は、今の世界マップ（島のマスを 1 ピクセルで描く小さな地図）の上に置く印で、幅 16・高さ 12 ほどの真横から見た船です。小さな軍艦（艦橋と砲の付いた灰色）・フリゲート（同じ色で一回り長く、艦橋の上にレーダーの塔）・潜水艦（水面に出た細長い船体と塔）・輸送船（今の輸送船の色の箱を積んだ船）の 4 つ。
- 戦場と占領のマス: 戦場は地面の焦げ跡（暗い茶の斑点）、占領は小さな柵と見張り台。壊れた施設は、今の施設の絵を使わず、崩れた壁の低い塊の共通の絵を 1 つにします。核の汚染が残るマスは、地形の上に灰色がかった斑点を重ねる絵です。

### 確かめ方

- 見本ページで、今の工場・港・住宅の隣に並べて、色の濃さと光の向きがそろっているか、0.25 倍で何の施設か分かるかを見ます。
- 下の「見直しの観点」の 5（光・色合い・線の太さ）と 6（文字を入れない）を、軍事の絵では特に見ます。

- 自分で（または AI に）新しく描いた絵だけを使います。他のゲームや素材集の絵を写す・なぞる・似せることはしません。
- 外部の素材を使うなら CC0・MIT など MIT と両立するものだけで、出典の URL とライセンスを書きます。
  出典やライセンスが分からないものは使いません。
- 足した絵は同じ PR で [THIRD_PARTY.md](../THIRD_PARTY.md) の「絵・音などの素材」に、ファイルかフォルダの
  パス・作った人（AI で作ったときはその道具の名前と、依頼した人）・ライセンス・出典を書きます。
  この行がないと自動テストが落ちます。

## 確かめ方

1. `python manage.py setup_dev` と `python manage.py runserver` で動かします。
2. **見本ページ** http://127.0.0.1:8000/static/map-preview.html を開きます。地形・施設・住宅の各段階・
   工事中・止まっている施設・首都・送電線・開発禁止を 1 つの島に並べ、島の画面と同じコードで描きます。
   `?sprites=0` で絵なし（色の箱）、`?scale=2` で拡大、`?overlay=population` で重ね表示と見比べられます。
   `?capital=<政治の建物>-<元首の建物>` で首都の絵を選べます。
   ドラッグとホイールで動かせます。
3. 実際の島 http://127.0.0.1:8000/islands/1/ でも、拡大・縮小して見ます。
4. 自動テスト: `pytest tests/server/test_theme_sprites.py`（名前・ファイル・大きさ・危ない SVG・出典を調べる）と、
   `ruff check . && ruff format --check .`、`pytest`。

## 見直しの観点

絵を足す PR は、次の観点で見直します（Claude が見直すときもこの順に見ます）。

1. 自動テストと CI が通っている。
2. 名前・大きさ・基準点がこの仕様どおりで、見本ページで地面から浮いたり沈んだりしていない。
3. 隣のマスとつなげたとき、地形の継ぎ目が目立たない。
4. 縮小しても施設が見分けられ、住宅の段階の違いが分かる。拡大しても粗くない。
5. 光の向き・色合い・線の太さが絵どうしでそろっていて、小さな地図の色と大きく違わない。
6. 文字や、コードが描くもの（印・枠・線）を絵に入れていない。
7. THIRD_PARTY.md に出典とライセンスがあり、他の作品に似せた絵がない。
8. 絵と、それを使うための最小限のコード以外を変えていない。
