# 多言語対応 ― Python の文言を gettext へ移す型

棚卸し（掲示板 #6108）と歯止め（ステップ1）に続く、ステップ2の見本の記録。
見本は `server/web/server_status.py`（管理画面の「サーバーの様子」）。
他のファイルへ広げるときは、この手順と注意点に沿う。

## 仕組みの決め

- Python の画面の文は、テンプレートと同じ Django の gettext に寄せる
  （`LOCALE_PATHS` は `server/locale` で設定済み）。
  パックのロケール（`packs/base/locale/`）は定義データの表示名用で、画面の文は Django 側。
- import は略さず正式名で書く（既存のコードに `_` の慣習がないため）。

```python
from django.utils.translation import gettext, gettext_lazy
```

## 手順

1. **評価の時点**で使い分ける。モジュールの読み込み時に決まる物（モジュールレベルの
   辞書・定数）は `gettext_lazy`（訳は使うときに決まる）。呼び出しのたびに組み立てる文
   （関数の中・プロパティ）は `gettext`。
2. **辞書は値だけ**を対象にする。キー（サービス名・知らせの印などの機械の識別子）は
   訳さない。
3. **f文字列は文全体を 1 つの文言（msgid）にし**、埋め込みは名前付きの置き場にして
   `.format(名前=値)` で渡す。断片ごとに訳さない（語順は言語ごとに違う）。
   式そのものは文言に入れず、数値の書式（桁区切り・小数桁）は値を整形してから渡す。

   ```python
   # 悪い例: f"{name}が止まっています" を断片で訳す
   # 良い例:
   gettext("{name}が止まっています").format(name=f["name"])
   ```

4. 同じ値を 2 か所で使うとき（単位など）は、同じ置き場の名前を繰り返す。
5. **対象外**: docstring とコメント（開発者向け）、機械向けの状態値（`"active"` など）、
   略号・単位記号だけの物（`"CPU"`・`"%"`・`"℃"`）。ただし表示名の辞書では、並びを
   揃えるため `"DB"` のように通した所もある。

## 注意点

- **数を含む文**: 単位・助数詞が数に直結する文は、ロシア語などで名詞の形が数によって
  変わる（棚卸しの (a): messages 約160件＋コード側 約290か所）。単位・助数詞が付く文を
  移す段では、`ngettext`（数の形で文を選ぶ gettext）の要否を文ごとに見る。
  この見本の `{days}日{hours}時間` のような組み立ては、その判定が要らない型。
- **名前を埋める文**: 施設名・品目名・国名などを埋める文は、言語によって格変化の
  扱いが要る（棚卸しの (b): messages 399件＋コード側 約300か所）。messages の引数
  177種に型（数量・単位・通貨・名前の種類）を持たせる段と合わせて判定する。
  この見本で埋めるのは数値と、呼び出し側で訳済みの名前（図の見出し）だけに留めた。
- **遅延の値の扱い**: `gettext_lazy` の値は「使うときに訳が決まる」代理物。
  保存・比較・JSON 化する所では `str()` で確定させる。この見本の辞書の値は画面表示
  だけに使うので、そのまま渡している。
- **訳ファイルは次の段**: `server/locale` の作成と `makemessages` はまだしていない。
  訳が無い間は画面に文言そのもの（日本語）が出るので、移しても見た目は変わらない。
  なお `makemessages` には gettext の道具（xgettext）が要り、むぎの VM には無いので、
  回すときは道具のある環境で。

## 歯止め（ガード）との関係

現在の数え方（`tools/spec/count_hardcoded_strings.py`）は、gettext の引数の文字列も
「直書き」として数える。そのため**移しただけでは件数は減らない**（この見本では
`server/web/server_status.py` が 36件 → 36件で、ベースライン以内なので試験は通る）。
移行を件数の減少として認めるには、数える側に「`gettext` / `gettext_lazy` /
`ngettext` の直接の引数は数えない」改修が要る。その改修のときに、移行済みファイルの
ベースラインを下げる（この見本なら 36 → 0）。

## 確かめ方

- 対象ファイルの試験を通す（見本では `tests/server/test_server_status.py`）。
- 画面を開き、日本語が移す前と同じに出ることを見る。
- `ruff check` と `ruff format --check` を通す。
