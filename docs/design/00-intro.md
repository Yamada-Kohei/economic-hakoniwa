## 読み方

- 決まりの番号で引くときは、まず [INDEX.md](INDEX.md)（決まり1つに1行。`python tools/spec/design_index.py write` で作る）か、`python tools/spec/design_index.py show MK-16` を使います。ファイルを丸ごと読まなくて済みます。
- 仕組みのファイル（1〜12 と 15）は同じ形です。頭の要約（範囲・コードの場所と試験・つながり）、「決まりの一覧」（番号・決まり・状態・設定の名前・試験）と「仮の決まり」、本文、「境目の表」（足りない・余る・0 になる・一部だけ・持ち主や相手がいない・時間がたつ、の 6 つの場面で誰が何をするか）、「前提と依存」、「見直しの記録」の順です。
- 決まりの番号は、タブごとの頭文字と 2 桁です（OV・PO・MK・LB・FM・FS・BK・IN・FX・PL・UI・GT・MI）。台帳や PR からはこの番号で指します。
- 状態は「決定」「仮」「作り直し予定（回N）」「決定（回N で作る）」の 4 つです。「仮」は本来の仕組みの代わりに置いた歯止めで、何の代わりか・いつ外すかを添えています。崩れを調べるときは、まず「仮」の行を疑います。
- **設計書に数字は書きません。** 率・量・ターン数・値段・上限などは `game.yaml` の設定の名前で指します（例: 為替の値幅は `fx.band`）。実物の数字は /mnt/project-files/settings/game-settings.md にあり、`python tools/spec/settings.py list <名前>` でも見られます。数字が設計書と `game.yaml` で違ったときは、カードで決めた数字でなければ `game.yaml` が正です。
- 境目の表の「現実の例」だけは、確かめの基準として数字を文で書いてかまいません（例: ひどい飢饉でも亡くなるのは 1 年以上かけて 1〜2 割）。設定の数字ではないからです。
- 実装の細部（Django のアプリ、DB の表、JSON API、段の表、命令の一覧、定義データの書き方、パック、規模、夜の点検）はリポジトリの `docs/` にあります。`docs/architecture.md`・`docs/modules.md`・`docs/defs.md`・`docs/packs.md`・`docs/scale.md`・`docs/nightly.md`・`docs/playtest.md` です。設計書はそこを指し、写しません。
- 決まったことは、決定を受けたスレッドがその日のうちに、PR で 2 か所に書きます。[13-decisions.md](13-decisions.md) に 1 行と、その仕組みのファイルの本文の書き直し（後ろに足さない）です。決まりの一覧を変えたら `python tools/spec/design_index.py write` で索引を作り直します（`tests/core/test_spec_design.py` がずれを見つけます）。ほかの所（経緯のタブ、memory、企画書、後回しの一覧のファイル）には新しく書きません。PR を出せないセッションの決定は、コーディネーターが記録のスレッドに回して書いてもらいます。
- 予定・未決・後回しは [14-plan.md](14-plan.md) だけに書きます。
- 用語は企画書と同じく「マス」「施設」「政治体制」「経済体制」を使います。コードの名前は英語で、`facility` のように添えます。1 ターンは箱庭暦の 1 か月です。

## 方針

- **リアルな仕組みから結果を出す。** 結果の数字を式の係数・上限・倍率で現実に寄せず、現実と同じ仕組み（誰が何を持ち、誰がいくらで買い、人がどう動くか）を入れ、その結果として現実に近い数字が出るようにします。セビーリャさんの言葉では「リアルなプロセスの結果、現実と同じになる、というのが望ましい。この件に限らずね」（2026年10月15日）です。
- 入力にしてよいのは、現実でも外から与えられるものです。好み（所得のうちサービスに使う割合）、技術（1 人が出せる量）、体の仕組み（何か月食べないと命に関わるか）、制度（国債の入札の決まり）などです。結果の側（失業率・利回り・餓死の速さ・物価）には係数を足しません。結果が現実から外れたら、足りない仕組みを探します。
- 現実の数字は「目安」として関門で見ます（12 確かめ方）。
- リアルさから来る難しさは残し、不具合とプレイが止まることは直します（2026年10月13日の方針）。
- 仕様の変更は歓迎します。変えるときの手順は /mnt/project-files/process/spec-change.md、スレッドの共通の決まりは /mnt/project-files/process/thread-rules.md です。
- 仕組みを作る・変える・直すときは、作る前に境目の表を書き、別の Claude（見直し役）に崩れる場面を挙げさせます。仕組みの形は、回・段・直しの始めにスレッドで 5〜8 行で見ていただきます（2026年10月17日のカード）。
- コア（`hakoniwa_core`）は Django からも DB からも切り離した純粋な Python で、Django（`server/`）は保存・画面・API だけを受け持ちます。細部は「1 全体とターンの流れ」と `docs/architecture.md` です。
- 人と AI が同じ入り口で遊べるようにします。命令・画面・数字を変える PR では、JSON API・MCP・国の要約と差分も同じ PR で合わせます（11 画面と統計）。
