# 12 確かめ方

作ったゲームが壊れていないこと、仕組みが現実の向きに動くことを、何でどう確かめるかを扱います。同じ種で同じ結果になる決まり、毎ターンの帳簿と世界の確かめ、部品の試験、一括シミュレーションと関門の目安、バランスの測り（場面・組・比べ・失業の内わけ）、揺さぶりの試験、夜の点検、規模の目安、標準の計画（プレイヤーの代わりに命令を並べる決め方）、重い計算を回す場所、試し遊び、設計書と索引の確かめです。帳簿の 4 つの確かめの中身はタブ 7、世界の段と島をまたぐお金の突き合わせの中身はタブ 9、統計の計算のしかたはタブ 11 にあります。マージと反映の手順は /mnt/project-files/process/thread-rules.md にあり、ここには確かめの決まりだけを書きます。

## コードの場所と試験

- 一括シミュレーション: `hakoniwa_core/simulate.py`（DB なしで同じ段を回す）
- 関門の目安と記録、崩れの見張り: `hakoniwa_core/gate.py`（目安と崩れの基準の値はゲームのルールでないので game.yaml でなくここに置く）
- バランスの測り（場面・組・比べ・失業の内わけ）: `hakoniwa_core/measure.py`、結果の使い回し `hakoniwa_core/reuse.py`
- 夜の点検: `hakoniwa_core/nightly.py`、X870 で回す台本 `tools/nightly/`、説明 [docs/nightly.md](../nightly.md)
- 標準の計画: `hakoniwa_core/autoplan.py`（数値もこのファイルに置く）
- 規模の測り方と記録: [docs/scale.md](../scale.md)
- 試し遊び: [docs/playtest.md](../playtest.md)、`tools/playtest/hk.py`
- 設計書の索引と設定の一覧: `tools/spec/design_index.py`、`tools/spec/settings.py`
- 試験: tests/core/test_engine.py、tests/core/test_gate.py、tests/core/test_measure.py、tests/core/test_measure_reuse.py、tests/core/test_collapse.py、tests/core/test_shocks.py、tests/core/test_nightly.py、tests/core/test_economy.py、tests/core/test_phase3_3.py、tests/core/test_phase3_4.py、tests/core/test_spec_design.py、tests/core/test_docs_match.py、tests/core/test_spec_settings.py、tests/server/test_phase1.py、tests/server/test_turns.py

## つながり

- 前提にしていること: 記録の段の帳簿の確かめ（タブ 1・7）、世界の確かめの段 `trade_check`（タブ 9）、統計の名前と計算（タブ 11）、命令の確かめ `check_order`（タブ 1）、乱数を島ごとに分ける決まり（タブ 1）。
- 前提にされていること: すべての仕組みを変える PR のマージの判断、バランス調整の回の比べ（タブ 14）、サーバーへの反映の判断。

## 仕組み

### 同じ種で同じ結果

- 乱数は世界の種から島ごと・段ごとに分けて作り、島の並び順や島の数で変わらないようにします（タブ 1）。同じ種なら同じ結果で、保存して読み込んでから続けても、まっすぐ回したときと同じ状態になります。
- 結果の同じは、世界の状態の指紋（`world_digest`）で比べます。測りの道具・夜の点検・計算を速くする直しは、同じ種で指紋が変わらないことを確かめてから入れます。
- サーバーで DB を通して回したターンと、メモリだけで回したターンも同じ結果になることを試験で確かめます。

### 毎ターンの確かめ

- 記録の段の最後に帳簿の 4 つの確かめ（タブ 7）を行い、崩れていれば例外を出してそのターンを失敗にします。サーバーは何も保存せず、ターンは進みません。
- 島をまたぐお金（外貨の持ち高と非居住者の預金、中央銀行どうしの融通、外国の国債）と運ぶ途中の荷は、世界の段 `trade_check` が毎ターン突き合わせ、合わなければ同じく止めます（タブ 9）。
- ターンが止まるのはゲームの不具合なので、夜の点検は「止まった」を一番重いものとして書き残します。
- どの段でも、例外が出たらターン全体を止めます（島ごとに分けて、その島の段だけ飛ばすことはしません）。市場・貿易・為替・送金は島をまたぐので、1 つの島の段だけ飛ばすと相手の島の帳簿と合わなくなり、食い違ったまま進んでしまうためです。お金がすべて複式の帳簿で動くことを守るほうを選び、止まったときはサーバーが管理者に知らせ、印を外して次の更新でやり直します。

### 部品の試験

- 板寄せの関数は、乱数で作った注文で「約定量が最大」「値幅を守る」「指値より不利な約定がない」「取り置いたお金を超えない」を確かめます。
- 帳簿の確かめは、わざと崩した帳簿（違う種類の間の仕訳・仕訳のない残高の変化・知らない種類・負の預金・形の悪い記帳）で失敗することを確かめます。
- フェーズ3 では、為替の板寄せ（片側だけのときに値幅ずつ動く）、非居住者の預金と外貨の持ち高の突き合わせ、航海の荷が消えないこと、議会の採決、政情の段階の境を部品で確かめます（タブ 9・10 の決まりの一覧の試験）。
- 試験は、回す場所と順で結果が変わらないように書きます（GT-43）。GitHub の確かめは `PYTHONWARNDEFAULTENCODING=1` で回し、文字コードを書かずにファイルを読み書きした所を誤りにします（`tests/conftest.py` の `filterwarnings`。Windows では cp932 になって落ちるため）。飛ばした試験はわけと一緒に最後に並べます（`pytest -rs`）。2026-10-31 に見直したとき、作った世界に警察・兵舎がない、国庫が細くて補助の付いた参入が起きない、の 3 件が黙って飛ばされ、何も確かめていませんでした。今は場面を組み立てて必ず確かめます。

### 一括シミュレーションと関門

- `python -m hakoniwa_core.simulate` は画面も DB もなしで同じ段を回します。`--autoplan` でどの島にも標準の計画で命令を並べ、`--gate` で関門の目安から外れたところを並べ、`--scenario` で場面を選び、`--out` で結果のまとめを、`--series` で島×ターンの時系列を書き出します。
- 関門は 50 島 × 300 ターンを標準の計画で回し、目安を見始めるターン（`gate.START`）から後の記録で目安に収まるかを見ます。島は市場・混合・計画経済をばらけさせ、鉱業資源もばらけさせます。時間がかかるので、ふだんの試験では回さず、環境の変数 `HAKONIWA_FULL_GATE=1` のときだけ回します。長い試し回しは X870 で回します。
- 目安の値はゲームのルールではなく確かめの基準なので、`gate.py` の頭に置き、game.yaml には置きません。目安から外れたところには種類（`gate.KINDS`）を付けます。

| 目安の種類 | 見るもの |
| --- | --- |
| 値段（`price`） | 売り買いのあった財の値段を初めの値段と比べ、物価指数の伸びで割った倍率（ほかの財と比べた値段）が決めた幅に収まる（目安を見る期間の値段だけで判定）。物価全体の上がり方は物価の目安で見るので、ここでは数えない（回5。年に6%ずつ物価が上がる島では、24年で値段が4倍になる）。人の手間が値段の財（サービスと小売り）は、物価指数でなく平均賃金の伸び（初めの賃金に対する倍率）で割る（回7 後半。GT-39） |
| 物価（`inflation`・`cpi_spread`） | 物価上昇率が決めた幅に収まる。後半の物価指数の振れ幅（標準偏差 ÷ 平均）が上限より小さい |
| 雇用（`unemployment`） | 失業率が決めた幅に収まる |
| 金利（`rate_high`・`rate_low`） | 政策金利と国債の利回りが決めた幅に収まる |
| 人口（`population_floor`・`population_cap`・`population_jump`） | 初めの人口に対して消えも爆発もせず、1 ターンで急に変わらない |
| 統計（`gdp_gap`） | GDP の生産の側と支出の側の差が上限より小さい |
| 企業と銀行（`firms`・`bank_cascade`） | 市場経済の島で民営工場の数の振れが収まる。同じ島で銀行の破綻が続かない |
| 為替と外国の資産（`fx`・`reserves`・`reserves_rise`） | 為替の 1 年の動きの平均が上限より小さい。外国の資産（外貨準備と外国の国債）の対年 GDP 比が上限を超えず、最後の期間に増え続けない |
| 世界（`titles`・`goods_made`・`goods_traded`） | 称号が 1 つの島に集まらない。どの財もどこかの島で作られ、売り買いされる |
| 貿易（`trade_stopped`） | 輸出も輸入も 1 年続けて 0 の島がない |
| サービスで働く割合（`services_share`。回7） | 働く人のうちサービス（商業・金融・運輸・商社・公務・教育・治安）で働く割合が、1人あたりの実質の GDP に見合う幅（貧しい島 3〜4 割、豊かな島 6〜7 割） |

- ほかに、石炭の出ない島の失業率の平均と、財ごとの作った島と売り買いのあった島の数を記録し、回ごとに比べます。
- 現実の数字は「目安」として関門で見ます（タブ 0 の方針）。目安から外れたら目安をゆるめて合格にせず、仕組みから直します（2026-10-15 の回2 の方針）。外れが残る目安は、タブ 14 の後回しに置きます（物価上昇率は W-12、回7 で見ることは W-23）。

### 崩れの見張り

関門の目安（物価・失業率など、現実の平年並みか）とは別に、島が壊れていく兆しを 1 ターン目から数えます（2026-10-17 のやり直しの報告の I1・I2・I5）。目安は 120 ターン目からしか見ず、いつも 100〜300 件外れていたので、崩れが増えたかを読み取れませんでした。

- 数えるもの（`gate.py` の `COLLAPSE_KINDS`。島ごと・種類ごとに、崩れが始まったターン・当たったターンの数・中身を 1 行にする）:
  - 飢饉: 1 年に飢えで亡くなった人が、その初めの人口の `FAMINE_SHARE` 以上。ひどい飢饉でも亡くなるのは 1 年以上かけて 1〜2 割なので、その下の端を兆しにします。
  - 人口の大きな減り: 1 年で、国を出入りした人を除いて人口が `DROP_SHARE` より減る（出国は政策の結果なので除く）。
  - 品切れ: 島で作ったことのある財が、買いたい人がいるのに直近 `STOCKOUT_TURNS` ターンのうち `STOCKOUT_MISSING` ターン以上売りに出ない。初めの在庫で売っただけの作れない財は数えません（作られない財は目安の goods_made で見る）。
  - 取引が成り立たない: 前は取引のあった財が、売りも買いもあるのに `NO_TRADE_TURNS` ターン続けて約定 0。
  - 品切れと取引が成り立たないのは 1 年で見ます。半年では、main の 50 島の世界で 7〜9 割の島が当たり、増えたかを読み取れなかったためです（2026-10-18 の quick）。
  - 作り方の群れ: 1 ターンに同じ種類の施設の `HERD_SHARE` 以上（`HERD_MIN` 以上）が作り方を替える。
  - 国の賃金の未払いが `LONG_TURNS` ターン続く、銀行が中央銀行から借りたままなのが `LONG_TURNS` ターン続く。国庫は国債と支出の削りで 0 にならず、銀行は準備が足りなければ同じターンに借りるか破綻するので、手元が 0 になるかではなく、この形で詰まりを見ます。
  - 理由の出ない停止: 地図の上の人の働く施設が、稼働率 0 なのに動けない理由を出さないのが `SILENT_TURNS` ターン続く。
  - 企業ごとの倒産の連鎖（回7）: 1 つの企業の施設が `FIRM_CASCADE_TURNS`（3 ターン）のうちに `CASCADE_MIN` 以上、差し押さえになる。企業が自分で閉じた施設は数えない（倒産は同じ企業の貸し借りでほぼ同じターンに移るため）。
  - 企業の倒産は回7 前半では main に比べる相手がないので、マージのお願いでは別に数える（回7 後半から main と比べる）。
  - 品切れの見張りは、店が売りに出ていなくても直売・屋台が小売りを売ったターンを、小売りの品切れに数えない（回7）。
  - 手当のない国の飢え（回7）: 失業手当 0 の島で、1 年に飢えで亡くなった人が初めの人口の `FAMINE_SHARE` 以上（飢饉の一部を、支え合いが効いているかを見るために分けて数える）。
- 測りの結果には目安の窓とは別に崩れの一覧を書き、`measure compare` の頭に、組・種類ごとの崩れの島の数の前と後（増えたら「増えた」）と、新しく崩れた島を並べます。その次に目安の外れの数を、場面とターン数ごとに種の平均で並べます。崩れの増えはマージの判断に使い、目安は合否に使わず PR に書きます。
- 崩れごとに、崩れが始まったターンの `SNAPSHOT_BEFORE` ターン前まで回して世界を写す命令（`simulate --save`）を付けます。同じ種・同じ版なら同じ世界になるので、毎ターン写さず、見つけてから作り直します。写しから続ける（`simulate --load`）と、そこから崩れが育つ様子を調べられます。崩れの見張りは写しのターンから数え直すので、1 年を見る種類は 1 年たってから出ます。
- でたらめな国の組には崩れの見張りを付けません（遊ぶ人の命令で崩れたのか、仕組みの崩れか区別できないため）。

### バランスの測り

後の回の効き目を同じ物差しで比べるための道具です（回2、PR #50）。

- **GDP の差**（Codex A08）: 生産の側と支出の側の差を、2 つの絶対値の大きい方で割ります。分母は小さすぎる額（1 人の 1 ターンの賃金など）より小さくしません。片方だけが 0・両方が負・符号が違うときも差を見逃しません。
- **値段の期間**（Codex B02）: 値段にターンを付けて記録し、目安を見る期間の値段だけで判定します（前は売り買いのあったターンの末尾を切り出していたので、期間の外の値段が混ざった）。
- **最初の 1 年**: 関門はターン 120 からしか見ないので、建国直後の縮みが出ません。12 ターン目の雇用と実質の生産の 1 ターン目との比を記録し、回 1 の値より悪くならないかを見ます。合否には使いません。
- **失業の内わけ**（Codex B01）: 島×ターンごとに、働き手の行き先（仕事・村の自給・失業）、施設が人を雇わなかった理由（売れ行き・原料・電力・資金・働き手・技術者・止まっている）、通勤圏で求人と失業者が出会えていないか、需要の内わけ（家計・工事・政府・輸出入）、民営が参入しなかった理由、機械と鋼材を誰が買ったかを、時系列に書き出します。
- **場面**（`measure.SCENARIOS`）:

| 場面 | 中身 | 関門に数える目安 |
| --- | --- | --- |
| 標準の計画 | 50 島、標準の計画 | 全部 |
| 命令なし | 50 島、命令を出さない（初めて遊ぶ人や放っておかれた国） | 崩れないかの目安だけ（GDP の差・値段・金利・人口・銀行の連鎖など）。失業率や物価は見るだけ |
| 中央銀行を独立させた国 | 標準の計画に、中央銀行を独立させる命令を足す。議会で否決されたら通るまで毎ターン出し直す（民主主義の島は、建国した最初のターンは賛成がちょうど半分で否決される） | 全部 |
| 少ない島の世界 | 4 島、海外の商人が去った後も貿易が続くか（Codex B03） | 全部 |
| どの島も移民を受け入れる世界 | 初めのターンにどの島も移民の受け入れを開く（回3） | 全部 |

- **組**（`measure.SETS`）: quick は回ごとの比べ（標準の計画の種 1・2 の 300 ターンと、ほかの場面）、full は回の終わりに一度だけ（標準の計画と少ない島と移民の世界は種 1〜4 か 1・2 の 500 ターン、命令なしと独立は 300 ターン）。300 ターンは初めに配った船の寿命の直前で終わるので、full で 500 ターンも見ます（Codex B04・E31）。
- 結果は `python -m hakoniwa_core.measure compare` で 2 つを並べます。元にする結果は共有フォルダの balance/runs/ に置きます。
- **結果の使い回し**（GT-41）: 結果の JSON に、回したときの計算の中身の指紋（`code_fingerprint`）を書きます。`measure batch --reuse <前の結果のフォルダ>` は、同じ組の結果で指紋が今と同じものを回さずに写します（`.log` に写した元を書く）。main の結果を何度も回し直さずに済みます。指紋は `hakoniwa_core/` の全部、`game.yaml`、`packs_dirs` と `schemas_dir` の中身で、改行は LF にそろえて数えます。`server/`・`tests/`・`docs/` と Python の版は数えません（3.12・3.13・3.14 で状態の指紋が一致することを確かめてある）。指紋が違う・書いていない・時系列がない・壊れているときは使わず回します（回しすぎる側に倒す）。

### 揺さぶりの試験

数島で揺さぶりを起こし、その後回して、向きが正しく帳簿が崩れないことを確かめます。

| 試験 | 起こすこと | 確かめること |
| --- | --- | --- |
| 刷りすぎ | 毎ターン、国債を大きく中央銀行が直接引き受ける | 物価が上がる。値段が桁あふれしない |
| 利上げ | 政策金利を上げる | 預金と融資の金利が上がる |
| 銀行の破綻 | 1 つの銀行の融資の一部を貸し倒れにする | 破綻処理のそれぞれで、預金と帳簿が合い、連鎖しない |
| 国債の不履行 | 利払いを止める | 利回りが跳ね上がり、持っていた銀行の自己資本が減る |
| 発電所の停止 | 災害で発電所を止める | 電気料金が値幅の中で動き、停電の後に戻る |
| 計画経済 | 計画経済の島だけで回す | 倒産が起きず、物不足が出ても止まらない |
| 移し替え | 前の段の世界を移し替えて回す | 最初の 12 ターンで生産量が大きく落ちない |
| 全部の国から禁輸 | 全部の国がある島を禁輸する | 海外の商人と島の中だけで回り続ける |
| 固定相場の準備切れ | 外貨準備の少ない国が固定相場にする | 準備が尽きたターンに固定が外れ、変動相場に戻る |
| 中央銀行の大量の引き受け | 物価を大きく上げる | 政情がデモから暴動まで下がり、止めれば戻る |
| 公定価格を原価の半分 | 計画経済の島で公定価格を下げる | 行列と強制貯蓄が増えるが、生産は止まらない |
| 決済通貨の島の生産を止める | 圏の決済通貨の島を 12 ターン止める | ほかの加盟国の輸入が減るだけで、帳簿も為替も壊れない（回6 で足す） |
| 船を全部失った島 | 船をなくす | 輸入が止まり、造船か買った船で持ち直す（回6 で足す） |

### 夜の点検

変えた後のゲームが、遊ぶ人より先に壊れていないかを確かめるため、空いている夜に大きめの一括シミュレーションを回します（2026-10-16 のカード）。数字は寄せず、見るだけです。道具の使い方と X870 での入れ方は docs/nightly.md にあります。

- **長い年月**: 標準の計画・命令なし・少ない島の世界を 100 年回し、関門の目安から外れた島の数を、測りの範囲とその後に分けて数えます。後の期間にだけ出た種類を「40 年より後に出た崩れ」として並べます。崩れの見張り（上の節）も 1 ターン目から数え、種類ごとに崩れた島の数と、いちばん早いものの写しの命令を並べます。
- **でたらめな国**: 50 島のうち一部の島が、毎ターン決まりの中ででたらめな命令を出します（残りは標準の計画）。命令は命令の形からでたらめに作り、画面と同じ確かめ（`check_order`）を通ったものだけを並べます。ターンの処理が例外で止まったら（サーバーならターンが進まなくなる）、そのターンと並べた命令を書き残し、命令の受け付けの確かめで出た例外（画面なら 500）も書き残します。
- 前の夜までに見つけたものの一覧と比べ、新しいものだけに「新」を付けます。新しいものが見つかった朝だけ知らせます。止まった組は、同じ版・同じ種で回せば同じターンで同じように止まります。
- 決めた時刻（既定は朝 6 時 30 分）になったら、走っている組を止めてまとめを書きます。組は途中の結果を書くので、止めた組もそこまでの分を見ます。

### 規模

- 既定の 50 島で、1 回のターン更新を 5 分以内に収めます。測り方（サンプルの世界を作って `run_turn --force`、DB なしの計算だけなら一括シミュレーション）と、後のターンほど遅くなっていた件の記録は docs/scale.md にあります。
- 後のターンほど 1 ターンが遅くなるのは、国債の銘柄の数に比例する仕事が残るためです。銘柄の数がこれほど増えてよいかは回5 で見ます。

### 標準の計画

- 一括シミュレーション（関門と測り）と開発用のサンプルの島で、プレイヤーの代わりに命令を並べる決め方です。サーバーの世界の国は動かしません（命令のない国は何もしない）。ゲームのルールではないので、数値は `autoplan.py` に置きます。
- 毎ターン、工事中の施設が少なければ、上から見て最初に足りないものを 1 つ建てます: 食料 → 発電 → 工事の資材 → 投入財 → 消費財 → 島で使っていない鉱業資源を使う施設（輸出向け）→ 入っている貿易圏で足りない物（輸出向け）→ 生産の連鎖（鉄鉱石 → 鋼鉄 → 機械）。投入財に余裕のない施設は建てません。
- ほかに、学校と大学、建てた施設の送電線と道路、育たない町の上下水道、失業手当、公共事業費の見直し（住民 1 人あたりを基本に、失業率が高ければ増やし、物価上昇率と返す力の比が高ければ減らす）、税の上げ下げ（GT-37）、飢饉の手と穀物の蓄え（GT-29）、教育費（学校と大学を全力で動かす年の費用に余裕を見た額）、電気料金の上限、工業団地の指定、国の倉庫の物を市場に売ることを決めます。
- 世界の側では、北と南に 1 つずつ誰でも入れる貿易圏を作り、貿易の始まった島をそれぞれに加盟させます（真ん中の行の島は両方。決済通貨は人口の一番多い加盟国）。商社は自動なので、貿易そのものは標準の計画に要りません。政治の命令は出しません。
- 飢饉のときの手（2026-10-17 のカード。GT-29）と財政の手（GT-37）は回5 で入れました。借金の歯止めで教育費も減らすことは W-63 で入れました（GT-27）。造船所を建てないこと（W-66）はタブ 14 にあります。標準の計画は試し回しのためのプレイヤー役で、方針は Claude が変えてよいです（2026-10-25 本人）。

## 前提と依存

### この仕組みが前提にしていること

- 乱数を島ごと・段ごとに分ける決まりと、状態の指紋（タブ 1）。

### この仕組みの結果を前提にしている仕組み

- バランス調整の回の比べと、回ごとの関門（タブ 14）。
- マージと反映の判断（thread-rules.md の「マージのお願い」「サーバーへの反映」）。
- かみ合い: 標準の計画 × 関門（標準の計画が弱いと、仕組みの崩れと決め方の弱さが区別できない。命令なしの場面と並べて見る）。測りの場面 × 議会（独立の命令が否決される島は出し直す）。夜の点検のでたらめな命令 × 画面の確かめ（確かめを通る命令だけを使うので、確かめの抜けは「受け付けの例外」として見つかる）。
