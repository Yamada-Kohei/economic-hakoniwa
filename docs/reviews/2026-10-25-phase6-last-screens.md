## AI の道具の変更

`codex-player` の `hk-run.py`・`hk300.py` などについて、アカウントごとの保存先を分ける処理と
UTF-8 出力の処理を確認した。鍵・ログイン情報・実際の接続先・私的なファイルを取り込んでいない。

- `--profile 名前`: ホームの `.hk-profiles.json` から接続先と保存先だけを選ぶ。鍵・cookie・差分は名前別。
  環境の別アカウントの鍵やログイン情報は使わない。設定の選択はプロセスごとで、選択中の国を自動保存しない。
- `profiles`: 設定名だけを表示し、鍵の中身を読まず、API を呼ばない。
- `facilities [島] --status 表示名`: 既存の施設 API を使い1施設1行。`--json` は元の API の JSON。
  国庫直轄で預金がない場合や決算未集計も区別する。他国の非公開情報は出さない。
- `check 島 @orders.json`: 1件、配列、`{"orders": [...]}` に対応。既存 API を1件ずつ呼び、
  失敗を含めて結果を返す。1件でも `ok: false` なら終了コード1。列の書き込みはしない。
  HTTP エラー時はそこで止まる。前の命令の効果・資材の取り合い・実行時の議会は予行しない。

## 気になっている点（Claude 側へお願いしたい Python と値）

### U02: 大きな変化の選択

現在の `summary.indicators` は `key`・`label`・`before`・`now` の表示文字列だけ。
今回は失業・食料・電力・幸福度・GDP の順で、前の値がある変化を最大3件出している。
変化の絶対値での順位付けや警戒水準の判定は行っていない。

ゲーム側の基準で選ぶ場合、`summary` と画面に、例えば
`notable_changes: [{key, label, before, now, severity, destination}]` が欲しい。
大きな変化の基準は定義/設定側で決め、未観測の前の値は増減として数えない。
原因は数値から言い切らず、既存の観測された停止理由があるときだけ添える。
同じ結果を JSON API・MCP・差分にも反映してほしい（UI-02・UI-23・UI-28・UI-30）。

### U05: 最も多くの国を比べられる初期通貨

`server/web/rankings.py::default_base` は自国、なければ貿易国の最小番号を返すまま。
候補通貨ごとに `_factors` の換算経路と比較対象の統計を確認し、比較できる国数が最大の通貨を選んでほしい。
明示的な `?base=` は優先し、同数なら自国、さらに同数なら島番号順など、決定的な選び方にする。
未集計の国は「換算できない国」と混ぜない。GDP が0の国も比較対象に数える。

画面/API 共通で、部門ごとの `compared_count`・`unconverted_count` と
`unobserved_count`、通貨候補ごとの `comparable_count` があると、JS なしでも範囲が伝わる。
換算できない国の一覧自体は現行の `categories[].rows` に既にある。
今回の件数表示はその行を数えるだけ。初期通貨の変更後は、設計書11の自国優先の説明も合わせてほしい。

### U06: 施設番号でのログ検索

現行の `display.log_entries` は `turn`・`kind`・`text`・任意の `tile`。
今回は既存の `GET .../log?from=&to=` の範囲を読み、`kind` と `tile` を絞っている。
マスを持たない運送業などや、施設の番号だけで残した出来事には対応できない。

必要なら公開できる行に `facility`（番号）と `kind_label`（出来事の種類の表示名）が欲しい。
現行では種類名の代わりに、その種類の代表の文を選択肢に使っている。
サーバー側で `facility`・`kind`・`from`・`to` の検索を行う場合も、
`visible_logs` の軍事情報・伏せる失敗の制限を必ず先に適用し、MCP のログにも同じ引数を反映してほしい。

### U07: 手動運用と予定未設定の区別・AI との同等性

テンプレートから `World.paused`・`updating_since`・`next_turn_at` を読んで表示した。
`next_turn_at` がないだけでは手動運用を断定できず、現在は「手動で進める運用か、予定の設定待ち」と表示する。
予定超過の判定は閲覧端末の時計による。サーバーの最新状態は再読み込みが必要。

画面/API/MCP 共通の `turn_schedule` に、`mode: manual|scheduled`、`paused`、
`updating_since`、`next_turn_at`、`server_now` が欲しい。
現行の `summary`・`me` は次回時刻だけなので、停止と更新中も読めるようにしてほしい。
手動と定期の明確な区別、サーバー時刻による遅れ判定は、その値を受けてから仕上げる。

### U08: 未観測・気配・約定を値として区別

注記と、既に `null`/欠測になっているグラフの扱いは追加した。
`reports.market_table` や `display.goods_table` などには、統計名がない場合に
`stats.get(..., 0)` で0へそろえる所があり、テンプレートでは元の欠測へ戻せない。
市場の価格も `price` と売買量だけでは、前の値の持ち越し・新しい気配・約定価格を正確に区別できない。

観測できていない値は `null` または項目省略とし、価格には
`price_kind: quote|trade|carried|unobserved` と `observed_turn` が欲しい。
0 と未集計、気配と約定を同じ文字列へ畳む前の情報を画面/API/MCP 共通にしてほしい。
実質 GDP の新計算は今回求めていない。現行の名目額の説明だけ追加した。

### U10: 幸福度の内訳

`population.happiness` は家計の層とマスごとの値を使い、重みの移行・人数での平均・
上下限と丸めもあるため、画面の全国指標から足し直すと一致しない。
現在の API は合計と一部の元の指標で、寄与点そのものを返していない。

政情の内訳と同じく、持ち主だけに
`happiness_breakdown: {turn, total, raw_total, cap, rounding_adjustment, components}` が欲しい。
`components` は `[{key, label, contribution, value, unit, destination}]` とし、
基礎点・食料・食事の質・働き口・電力・衣料・ぜいたく品・上下水道・教育・汚染・
実質賃金の低下・物価上昇・飢え・遅配・過密など、実際に使った要因を返してほしい。
人数による平均と上下限で合計が変わる分も説明できる形にする。
`economy/overview`・国の要約・MCP の経済の報告から同じ内訳を読めるようにしてほしい。
今回の経済画面には、数値の寄与がまだ出ないことと調べる先だけを示している。
