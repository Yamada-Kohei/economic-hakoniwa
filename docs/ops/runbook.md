# 運用の手順

> 状態: 案を台本に直した段階。段 8-6 の通し稽古で一度ずつ通し、通した結果に合わせて直す。
> 「誰が」: ふだんは Claude（X870 から ssh）。セビーリャさんにお願いするのは、物の取り替え・マージ・開けてよいの一言・Cloudflare の画面だけ。
> ゲーム本体の守り（https・ログインの上限など）の見直しは、セビーリャさんが頼む別の AI。

入るとき: `ssh sevilla@sevilla-server`（X870 から）。ゲームの状態 `systemctl status hakoniwa-gunicorn`、記録 `journalctl -u hakoniwa-gunicorn -n 100`
（アクセスの記録は出さない決まり。エラーだけが残る）。台本の結果は `/srv/hakoniwa/state/last` と `deploy.log`。

## 1. 新しい版を出す

使うとき: 直しがまとまって LAN のサーバー（8000）で確かめたとき（目安は週 1 回まで。急ぎはその都度）。

1. Claude が `release` の枝を main のその版に進める PR を出す。本文に「遊ぶ人に見える変化」「DB の移し替え（migration）の有無」「戻し方」を書く。
2. セビーリャさんがマージする。
3. 機械が 5 分おきに見て、次のターンまで 10 分以上あるときだけ進める: 本番の DB の写し（試し用の DB）で migrate・check_defs・3 ターン・主なページを試す → ターンの鍵を取り、ゲームを止めて DB を控える → 新しい版にして migrate・静的ファイル・再起動 → 主なページが 200 か確かめる。止まるのは数十秒で、その間は「更新中です」の画面。
4. 入ったら ntfy に「ゲームの新しい版が入りました」。遊ぶ人に見える変化は、Claude が管理者として掲示板に書く。
5. 失敗したら DB の控えと前の版に自動で戻り、ntfy に知らせが来る。Claude が原因を直し、`main` からもう一度出す。失敗した版は、枝がさらに進むまで試し直さない（`state/failed-<コミット>`）。

確かめ: `cat /srv/hakoniwa/state/last`、`curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: hakoniwa.sevilla-lab.com' http://127.0.0.1:8080/`

その他:
- 反映だけを止める: `touch /srv/hakoniwa/state/paused`（消せば再開。ターンは進み続ける）。
- 写しの試しだけを回す: `sudo -u hakoniwa bash -c 'set -a; . /etc/hakoniwa/hakoniwa.env; set +a; /usr/local/lib/hakoniwa/hakoniwa-deploy --trial origin/release'`
- 台本・サービスの定義を変えた版を出した後: `sudo /srv/hakoniwa/app/tools/deploy/prod/install.sh all`。

## 2. 入れた後に困ったとき（戻す）

- DB の移し替えのない版どうし: `release` の枝を前の版に戻す PR を出してマージする（新しい版と同じ流れで入る）。
- 移し替えのある版: 戻さず、直しを前に出す（戻すと DB と合わなくなる）。
- どうしても戻すとき: 反映の前の控え `/srv/hakoniwa/var/predeploy/pre-<コミット>-<日時>.dump` に戻す。控えの後のターンは失われる。
  ```sh
  sudo systemctl stop hakoniwa-gunicorn
  # DATABASE_URL を読んで: スキーマを空にして pg_restore --no-owner -d "$DATABASE_URL" <控え>
  git -C /srv/hakoniwa/app reset --hard <前の版>  # 台本の restore と同じ手順。実際の打ち方は通し稽古で確かめて書く
  sudo systemctl start hakoniwa-gunicorn
  ```
- ターンの計算の不具合: 管理画面の巻き戻し（ゲームの中の写し、ターンごと）。セビーリャさんの一言の後に Claude が行う。

## 3. 写しと戻し

| 壊れ方 | 戻し方 | 失うもの | 誰が |
|---|---|---|---|
| ターンの計算の不具合 | ゲームの中の写し（ターンごと）から管理画面で巻き戻す | 戻した後のターン | Claude（セビーリャさんの一言の後） |
| 反映で DB が崩れた | 自動の反映が控えから戻す | なし | 自動 |
| DB の中身が壊れた・消えた | `/srv/backup/db/` の毎晩の写しから入れ直す | 最後の写しの後の分（最大 1 日） | Claude |
| NVMe が壊れた | 新しい円盤に建て方（[build.md](build.md)）どおり入れ直し、HDD の写しから戻す | 最大 1 日 | 円盤の取り替えと OS の入れ直しはセビーリャさん、その後は Claude |
| HDD が壊れた | 取り替えて、写しを取り直す。ゲームは止まらない | 古い写し | 取り替えはセビーリャさん |
| 機械ごとなくなる（火事・盗難） | 戻せない。新しい世界で始め直す（10-26 に家の外の写しを作らないと決めたときに受け入れた） | 全部 | — |

毎晩の写しの取り方: `hakoniwa-backup`（03:20）。写しの指紋は `/srv/backup/db/SHA256SUMS` と、ntfy（本人のスマホの履歴）の知らせに残る。入られた疑いのときは、この 2 つを照らす。
月 1 日の 05:10 に最新の写しを試し用の DB に戻して 1 ターン回し、結果を ntfy に送る。手で確かめるとき: `sudo /usr/local/lib/hakoniwa/hakoniwa-restore-check [--file <写し>]`。

## 4. 止まったとき

| 知らせ | まずすること | 誰が |
|---|---|---|
| ターンが進まない（ntfy「ターンが進んでいません」「ターン更新に失敗」） | `journalctl -u hakoniwa-turn -n 50`。停電や回線なら戻るのを待ち、戻った後にターンが正しく続くか見る（止まっていた間の分を一度に進めない作りだが、通し稽古で確かめる）。不具合なら直して `run_turn --force`、または巻き戻す | Claude |
| 外から開けない（遊ぶ人の声） | トンネル（cloudflared）→ Caddy → gunicorn の順に `systemctl status`。Cloudflare の側の障害なら待つ | Claude |
| 反映の失敗（ntfy） | `state/last` と `deploy.log`。前の版で動いているかを確かめ、原因を直す | Claude |
| ディスクが 70% を超えた（ntfy） | 記録と写しの量を見て、減らすか円盤を足すかを相談する | Claude（円盤はセビーリャさん） |

半日を超えて止まるときは掲示板に書く。機械ごと止まっている間は知らせる場所がないが、止まるのはかまわないという 10-25 の方針どおり受け入れる。

## 5. 止めるボタン（外から入れなくする、軽い順）

| 押し方 | 誰が、どこから | どうなるか | 戻し方 |
|---|---|---|---|
| 1 Access を掛け直す | セビーリャさんがスマホの Cloudflare の画面から | セビーリャさんだけ入れる状態に戻る | Access を外す |
| 2 トンネルを止める | Claude が X870 から `sudo systemctl stop cloudflared` | 外からは誰も届かない。家の中では動き続ける | `sudo systemctl start cloudflared` |

## 6. 入られた疑いのとき

使うとき: ルーターの見張りが区画を切り離した、機械の中の見張りが身に覚えのない変化（ssh ログイン・鍵・待ち受け・台本・手の変更）を知らせた、ゲームの外から入られた形跡を見つけた。
重大度は、家の側に触れた（見張りが切り離した）なら SEV1、機械の中の変化だけなら SEV2 として扱う。

1. **区画を切り離す**（見張りが自動で、または Claude）。切り離したまま戻さない。セビーリャさんのスマホに知らせが届く。
2. **機械の外の記録を正とする**: ルーターの止めた記録（`/root/game-watch.log`）・Cloudflare の画面・ntfy の履歴に残した知らせ（写しの指紋）。機械の中の記録は書き換えられているものとして扱う。
3. **怪しくなった時点を決め**、それより前の夜の写しを選ぶ。写しの指紋を、ntfy の履歴に残した指紋と照らし、合うものだけを使う。
4. **OS から入れ直す**（USB からの入れ直しをセビーリャさんに 1 回お願いする）。その後は [build.md](build.md) どおり Claude が入れ、照らした写しから戻す。
5. **秘密を全部作り直す**（Django の鍵・DB のパスワード・トンネル・ssh の鍵）。遊ぶ人のログインは全部切れる。
6. 遊ぶ人のパスワードの写し（元に戻せない形）が漏れたかもしれないときは、掲示板で、同じパスワードを他でも使っている人に変えるよう知らせる。
7. **どこから入られたかを調べて塞ぐ**（ゲームの穴なら本人が頼む別の AI、機械やルーターの設定なら Claude）。
8. 閉じ込めの試しを回し直し、セビーリャさんの「開けてよい」をもう一度もらってから開ける。経緯を家の資料の保管庫に書く。

終わったら振り返りを書く（誰も責めない形で）: 何が起きたか／いつ気づいたか／影響（漏れたかもしれないもの）／原因／直したこと／次に同じことを早く見つけるために足すこと。置き場は家の資料の保管庫。

## 8. HP の版

HP は別の担当（Codex）が `Yamada-Kohei/Sevilla-Homepage` の `release` の枝に版を積む。機械が 5 分おきに取り、確かめて切り替える
（枝の一番上は `public/` と `release.json` だけ、symlink なし、500MB まで。今の版と前の 5 版を残す）。
確かめに通らなければ前の版のまま配り、ntfy で知らせる。止める: `touch /srv/hp/paused`。前の版に向け直す:
`sudo -u hp ln -sfn releases/<コミット>/public /srv/hp/public.new && sudo -u hp mv -T /srv/hp/public.new /srv/hp/public`（急ぐとき。枝の側も前の版を新しいコミットとして積み直してもらう）。
