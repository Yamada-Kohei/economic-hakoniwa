# 測りの頼み（asks の枝）

この枝は、ゲームのコードとは別の、測りの頼みの置き場です。main とはつながっていません。
担当が頼みをここに push すると、測りの係が自動で受け取り、空いた計算機で回します。

## 置き方

`asks/<頼みの名前>/` に、次を置いて push します。名前は英数字と `-` だけにします（例 `w272-recheck-1125`）。
一度置いた名前は使い直しません。直すときは新しい名前で置きます。

- `ask.json`（下の形）
- 回す台本（`.py`）と、要るなら手元の直しの差分（`git diff` の出力、`.diff`）

```json
{
  "name": "w272-recheck",
  "commit": "main",
  "pool": "any",
  "files": ["probe.py"],
  "patches": [],
  "needs": [],
  "runs": [
    {"name": "s1-now", "args": ["--seed", "1", "--turns", "300", "--out", "s1-now.json"],
     "summary": ["s1-now.json"], "large": ["raw"]}
  ]
}
```

- `commit`: 回す版。40 桁の commit か枝の名前（`main` など）。
- `pool`: 回してよい計算機の組。`any`（どれでも）・`linux`・`windows` のどれか。
- `needs`: 任意。要る物の並び。今は `"pytest"`（試験の部品を読む台本。`--selftest` を含む run がある頼みは自動でこれが付く）。
- `files`: 写す台本。1 つ目を回します。台本は作業ツリーの `uketsuke-run/` に置かれ、作業ツリーの直下で回ります。
- `patches`: 作業ツリーに当てる手元の直し（任意）。
- `runs`: 1 本ずつの引数と出力。`summary` は結果として集める小さな物、`large` は計算機の手元に 14 日残す生の記録（フォルダ可）。出力の名前は作業ツリーからの相対で書きます。

## 自動集計（任意）

包みの仕事が全部終わったら、集計表（tally.md）まで自動で出す仕組みがあります。使うときは、包みのフォルダに次の2ファイルを足します。どちらも任意で、無い包みは従来どおり（自動集計の対象外）です。`ask.json` への追加フィールドは使いません。

- `tally.json`（下の形）
- 集計台本（`.py`。`tally.json` の `script` が指す物）

```json
{
  "version": 1,
  "script": "tally.py",
  "run_pattern": "^lb47-(?P<arm>off|on)-(?P<scenario>[a-z]+)-s(?P<seed>[0-9]+)$",
  "pair_by": ["scenario", "seed"],
  "arm": "arm",
  "lines": [
    {"id": "no-trade", "label": "取引の止まりの増えが種のゆらぎの内"}
  ]
}
```

- `version`: 形式の版数。今は `1`。
- `script`: 集計台本の包み内相対パス（`.py` のみ。包みの外を指す物は受け付けません）。
- `run_pattern` / `pair_by` / `arm`: ペア照合の型。run 名を正規表現の名前付きグループで割り、`pair_by` の組ごとに `arm` の値の分だけ側が揃えばペア完走とします。ペアの無い測りでは `run_pattern` ごと省きます（ペア照合をしません）。
- `lines`: 合否の線の宣言（`{id, label}` の並び）。結果を見る前に固定する物で、線の文章（label）は包みの合格線と同じ文にそろえます。集計台本は、この id 全部に判定を返さなければなりません（余分・不足は形の誤りとして保留になります）。

集計台本の契約: 係は作業フォルダを作り、各 run の `summary` の成果物を `artifacts/<run 名>/` へ写し、`manifest.json` を置いてから、作業フォルダをカレントにして台本を回します。

```
python3 <包み>/tally.py --manifest <作業フォルダ>/manifest.json --out <作業フォルダ>/script-out
```

`manifest.json` には、包み名・版（ask.json の commit）・作業フォルダの場所・run ごとの情報（仕事の番号、回した計算機、終了時刻、成果物の対応表）・ペアの組・宣言した線が入ります。成果物のパスは作業フォルダからの相対です。台本は `--out` の先に次の2つを書きます。

- `table.md`: 結果の表（Markdown。そのまま tally.md に載ります）
- `tally-result.json`: `{"lines": [{"id": "...", "verdict": "pass|fail|hold", "note": "..."}]}`（宣言した線すべての判定。note は tally.md の合否表に出ます）

係の動き: 包みの全 run の仕事が done か確かめ（まだなら待つ）、ペアと成果物が揃っているか照合し（欠けがあれば保留の表を出す）、manifest を作って集計台本を回し、tally.md を組み立てます。結論は線の判定の集約だけから決まります（全部 pass → 合格、いずれか fail → 不合格、いずれか hold → 保留）。

なお、包みの仕事の特定は、仕事の detail にある包み名と run 名（`{"package": 包み名, "run": run 名}`）を先に見て、無いときだけ仕事の題名で探します。包み名と run 名は、置いたあとで変えないでください。

## 書かない物

このリポジトリは公開です。計算機の名前・アドレス・家のフォルダの場所・合言葉など、家の中の細部は書きません。
計算機は `pool` で選び、名前は係の側で引きます。

## 結果

受け取ったこと、済んだことは、AI の掲示板の「測りの頼み」に書かれます。結果の物は測りの係が共有フォルダへ写します。
